# Эталон Java и общая подготовка финального задания — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подготовить общую основу четырёх самостоятельных выдач и полный эталон проекта автоматизации на Java.

**Architecture:** Общий стенд собирается один раз и копируется в четыре `participant/stand/`; исходники остаются только в общем `jury/`. Java-эталон — отдельный Maven-проект жюри, созданный с нуля, с проверками API, AMQP и БД. Ожидаемые результаты соответствуют ТЗ, известные отклонения стенда явно отражены в отчёте.

**Tech Stack:** Java 17 с обязательной совместимостью с Java 21, Maven, JUnit Jupiter 5.13.4, RestAssured 5.5.6, RabbitMQ Java client 5.37.0, H2 2.5.252, Jackson 2.20.0, AssertJ 3.27.6, Awaitility 4.3.0. Это исходный проверенный набор из прежнего каркаса; версии фиксируются в `pom.xml`, без обновления всей экосистемы.

**Spec:** [Общие требования и предложения для согласования](../specs/2026-11-10-final-four-directions-design.md).

**Статус:** согласован пользователем 10.11.2026, выполняется в `feat/final-reference-solutions`. Согласование включает общий этап и состав отклонений F10/F16/Н1.

## Global Constraints

- Базовые версии — Java 17 и Python 3.11; обязательна совместимость с Java 21 и актуальными стабильными версиями CPython новее 3.11. Проверки совместимости дополняют базовые. Python не обязателен для участника ручного направления.
- Четыре направления: `1a-java`, `1b-manual`, `1c-load`, `1d-python`; общий код не дублируется, готовый стенд дублируется.
- Java стенда — 17 и 21, целевой байткод — Java 17; Docker не требуется; стандартная история — 30 000 переводов.
- Инструкции участнику — Markdown; готовых тестов и `starters/` в выдаче нет.
- Два функциональных отклонения — F10/F16; ограничение учёта — предмет нагрузочного эталона. Никаких баллов за число находок.
- Не менять задания рейтинга 1a–1d. Все изменения ограничены `final-task/`, его правилами Git и документацией репозитория.
- До исполнения — согласование пользователем; коммиты только в рабочей ветке. Публикация и слияние отдельно не выполняются.

## Review Focus

1. Выдача из чистого клона: JAR, runtime-библиотеки и ZIP консоли доступны без Maven и интернета — проверяет этап 2.
2. Граница суммы, лимита и денежное округление не превращаются в побочные падения — проверяют этапы 1 и 4.
3. Не пришедшее AMQP-событие даёт ограниченный таймаут с `transferId`, а не зависание — проверяет этап 3.
4. Тесты с глобальными часами и паузой учёта восстанавливают состояние при исключении — проверяют этапы 3–4.
5. Падение из-за подключения к БД не может быть засчитано как ожидаемый дефект продукта — проверяет этап 5.

## Этап 5. Отчёт, проверка результата и приёмка

**Интерфейс общего проверяющего инструмента:** `python final-task/jury/tools/check_reference_results.py java <report-dir>` читает XML, сверяет полный ожидаемый состав тестов из каталога и два разрешённых assertion failure по testcase ID и меткам конкретных причин. Инфраструктурный error, пустой/усечённый отчёт, skip, неизвестное падение или исчезновение известного падения дают ненулевой код и объяснение. Схема Python использует тот же инструмент с аргументом `python` и отдельным перечнем testcase ID. Инструмент создаётся один раз на общем этапе 2; здесь проверяется его интеграция с реальным полным прогоном.

## Документация инструментов

При планировании проверены [фильтрация JUnit по тегам](https://github.com/junit-team/junit-framework/blob/main/documentation/modules/ROOT/pages/running-tests/build-support.adoc) и [параметризация](https://github.com/junit-team/junit-framework/blob/main/documentation/modules/ROOT/pages/writing-tests/parameterized-classes-and-tests.adoc). Версии Java-библиотек сохраняют совместимость существующего проверенного набора; перед исполнением проверить доступность закреплённых зависимостей без смены major-версий.
