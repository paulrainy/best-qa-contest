## Результат и границы

Отдельная папка `review-tasks/1b-testcase-review/participant/sandbox/` с Maven-проектом, русским README и браузерным приложением. Песочница реализует три BIQ, точные сообщения, роли, денежные границы, состояния заявок и продуктов. В ней нет намеренно заложенных дефектов или справочника ответов жюри.

Пользователь запускает Java-процесс, открывает локальный URL, входит одной из четырёх учётных записей и проходит операции. Данные сохраняются только в памяти процесса; доступны явный сброс и подготовка тестовых данных. Тестировщику не нужны внешние ЕФР, АБС, SMS-шлюз, база данных, Docker или Node.js.

Не входят: изменения пяти дефектов в кейсах, правки ключа и Excel, нагрузочные сценарии, реальные банковские интеграции, изменение 1a, развёртывание публичного сервиса. Песочница не обещает успешное выполнение дефектных кейсов как есть; расхождение с их ошибочным ожиданием является ожидаемым результатом.

## Запуск и устройство

- Java 17+, Maven; JDK `HttpServer`, Jackson для JSON. Не переносить из 1a зависимости на Selenide, Spring, Allure и Lombok, которые серверу не нужны.
- Доменная модель и проверки BIQ на Java; интерфейс на обычных HTML/CSS/JavaScript. Проверки интерфейса дублируют ограничения для удобства, но сервер защищает все бизнес-переходы самостоятельно.
- Maven-команда `mvn compile exec:java`. Документировать также сборку и запуск исполняемого JAR.
- Адрес по умолчанию `http://localhost:18081/efr/`, чтобы не конфликтовать с 1a на 18080. Порт настраивается `-Defr.port=...`. Сервер слушает локальный интерфейс и явно сообщает о занятом порте.
- Состояние процесса: пользователи, сессии, клиенты, счета, вклады, заявки, история и тестовые SMS. Последовательные операции изменения состояния атомарны; повторное исполнение заявки не зачисляет деньги повторно.
- Дата операции по умолчанию текущая локальная дата; для воспроизводимой проверки можно задать `efr.today=YYYY-MM-DD`. Все возрастные проверки, относительные даты вкладов и расчёт дней используют единый источник даты. Текущая дата операции видна пользователю.
- Пароли учебные, учётные записи `tst_oper01`, `tst_fk01`, `tst_kmtp01`, `tst_contr01` соответствуют общим шагам кейсов. Все принадлежат одному учебному филиалу; дополнительный контролёр другого филиала нужен для проверки ограничения области задач.

## Пользовательские потоки

### Вход, поиск и профиль

Вход показывает ФИО и русское имя роли. Поиск клиента по серии и номеру паспорта открывает профиль с ФИО, паспортом, статусом, FATCA и доступом ДБО. Блоки «Счета» и «Вклады» содержат номера, типы, суммы и статусы; детализация открывается через «Показать», действия — через «Операции». История операций доступна из карточки клиента. Создание клиента доступно со страницы поиска только разрешённым ролям. Контролёр работает через раздел «Задачи».

### BIQ-90101 — открытие вклада

- Право запуска и возраст проверяются независимо от интерфейса.
- Отсутствие FATCA блокирует запуск точным С1. «Отмена» оставляет профиль; «Заполнить форму» открывает «Самосертификация FATCA». Минимальное сохранение статуса позволяет продолжить эксперимент из кейса 900401.
- «Выбор вклада» → «Параметры вклада» → «Печать и подписание» с кнопками назад и отмены.
- Три продукта, минимальные суммы, сроки, неснижаемый остаток, валюта, ставка и доступность счёта списания — точно по таблицам BIQ. Десятичные расчёты через BigDecimal, отображение рублей и копеек в русском формате.
- Обязательные поля, включая выплату процентов и уполномоченное лицо, проверяются. Подписание доступно только после печати; печатная форма открывается в отдельной вкладке.
- Порог строго больше 1 000 000,00 и резидент США при любой сумме отправляют заявку контролёру. До исполнения вклад не появляется как открытый. Подтверждение создаёт вклад; отклонение требует комментария и не создаёт вклад.

### BIQ-90102 — закрытие счёта и вклада

- Действия зависят от роли, типа и статуса продукта. Для карточного счёта закрытия нет.
- Проверки идут в порядке BIQ: остаток/наличие счёта перечисления → возраст → ДБО. Ошибка ранней проверки не сопровождается сообщениями последующих.
- Счёт закрывается только при нуле, без контролёра при обоих способах подписания.
- Для вклада доступны только открытые текущие рублёвые счета перечисления. При отсутствии — точный С2 и предусмотренные кнопки. BIQ не описывает бизнес-процесс открытия счёта; переход «Открыть счёт» может вести к явно обозначенной подготовке учебных данных, не выдавая её за новую спецификацию банковской операции.
- Досрочность, точное сообщение, ставка 0,01 % и сумма выплаты рассчитываются по BIQ с округлением до копеек. Для «До востребования» нет сообщения о досрочности.
- Проверка документа выявила пробел BIQ: выплата срочного вклада в день окончания срока и позже не определена. Решение исполнителя: явно сообщать о неподдерживаемом расчёте, не придумывать финансовую формулу. Досрочные вклады и «До востребования», покрывающие текущие кейсы, поддерживаются. Ограничение документируется в README и при подготовке данных.
- Несовершеннолетнему обязателен существующий представитель, только бумажное подписание, без сообщения о неполном ДБО. В день 18-летия действует взрослый путь.
- Полный ДБО: электронное по умолчанию, возможность бумажного. Неполный ДБО: С4 с продолжением бумажного или отменой.
- SMS: отправка, шесть цифр, три попытки, точные С5/С6 и статус «Отменена» после исчерпания. Новый код не обнуляет уже потраченные попытки текущего подписания. Последнее — техническое решение для устойчивого учебного поведения, не новый оцениваемый пункт BIQ.
- Бумажное закрытие вклада идёт контролёру. Исполнение закрывает вклад и один раз зачисляет выплату; отклонение с причиной сохраняет вклад открытым.

### BIQ-90103 — создание клиента

- Форма и обязательность полей по BIQ; гражданство РФ только для чтения.
- Проверки последовательно: возраст → дубль текущего паспорта → ФИО и дата рождения → предыдущий паспорт при необходимости → финмониторинг → сохранение/контроль.
- Сравнение ФИО без регистра, Е/Ё равнозначны, наличие/отсутствие отчества различается.
- Предыдущий паспорт сверяется с текущим и историческими паспортами найденного клиента. Совпадение не создаёт новую карточку и позволяет открыть существующую.
- Отсутствие предыдущего паспорта не пропускает финмониторинг: после С5 и «Продолжить», когда они требуются, создаётся заявка на контроль.
- Совпадение со списком само по себе не требует контролёра. У активного клиента в истории есть «Передано в финмониторинг».
- Черновик недоступен в поиске; контролёр видит С8 и данные двойника. Подтверждение делает клиента активным; отмена требует комментария, удаляет черновик и оставляет заявку «Отменена».

## Данные и вспомогательные возможности

- Исходные данные включают продукты и паспорта, явно заданные в кейсах, а также необходимые примеры для остальных правил BIQ. Возрастные границы и даты открытых 30/73 дня назад вкладов рассчитываются относительно даты операции.
- Подготовка данных позволяет явно задать недостающее условие: клиента и паспорт, FATCA, ДБО, дату рождения, открытые/закрытые текущие и карточные счета, валюту, остаток и параметры вклада; для создания клиента — прежние паспорта и принадлежность к списку.
- Не исправлять недостающие данные кейса автоматически. Нет кнопок «Исправить кейс», подсветки пяти дефектов, привязок интерфейса к номерам дефектов или загрузки ключей жюри.
- Просмотр тестовых SMS показывает фактически отправленные сообщения и код после отправки. Это учебный заменитель телефона, а не лог внутреннего банковского сервиса.
- «Сбросить данные» требует явного действия и предупреждает о потере текущих учебных изменений. Сброс очищает заявки, SMS, сессии и возвращает исходные объекты. Перезапуск даёт такой же результат.
- Не создавать автоматически клиента из 900415 ради зависимого 900420: зависимость — дефект материала. Для независимой проверки правильного процесса данные задаются явно.

## Проверка

Проверки покрывают требования, а не ошибочные ожидания дефектных кейсов.

1. Доменный уровень: права каждой роли; границы возраста 14/18 и суммы; все ставки и поля; порядок блокирующих проверок; сравнение ФИО и паспортов; начисление и округление; переходы заявок и отсутствие повторных побочных эффектов.
2. HTTP: реальные запросы к локальному серверу, авторизация, неподходящие роли, подготовка/сброс, корректные ответы ошибок, защита от прямого вызова запрещённых действий.
3. Проверка охвата 20 кейсов на стороне жюри: после сброса и явно подготовленных условий проходят правильные ветки, соответствующие исправленным кейсам. Не включать таблицу ответов жюри в папку участника.
4. Браузер: вход, поиск, открытие с подтверждением и отклонением, оба способа закрытия, представитель, ошибочные SMS, обычное создание, дубль паспорта, предыдущий паспорт, финмониторинг и отмена контролёром. Проверить печатную вкладку, переходы назад/отмена и сохранение введённых значений.
5. Сборка, запуск через Maven и JAR, понятная ошибка занятого порта; README соответствует выполненным командам.
6. Проверить, что исходники кейсов, ключи, BIQ и файлы 1c/1a не изменены. При изменении общей документации запустить подходящие проверки генераторов.
