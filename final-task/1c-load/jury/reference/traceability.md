# Прослеживаемость нагрузочного эталона

Источник — [раздел 11 канонического ТЗ](../../../jury/source/spec.md#11-нефункциональные-требования). Численные результаты и ссылки на выбранные реальные запуски собраны в [отчёте](report.md). Функциональный каталог F01–F18 не превращается в квоту нагрузочных сценариев.

| Условие | Реализация и расчёт | Доказательство и граница |
| --- | --- | --- |
| 50 новых POST/с, OTHER 100,00 ₽, уникальный ключ | transfers.jmx, profiles/confirmation.properties; фактические начала POST в [30;180), допуск ±5% | Полный samples.jtl, profile.properties и measured/intervals в summary.json; контроль недодачи отдельно |
| Стандартная история 30 000 и 2000 пар | Один reset, проверка метрики строк, prepare_data.py, общий CSV, бюджет 100 000 запросов | initial.json, reset.json, accounts.csv, tests/test_data.py; reset во время прогона отсутствует |
| p95 принятого POST ≤500 мс | nearest-rank по elapsed всех корректных 202 измерительной когорты | samples.jtl, summary.json; тест 20 значений даёт 1900 мс; ошибки и прогрев не смешиваются с популяцией |
| ≥95% принятых в финальном статусе за ≤2 с | completedAt−createdAt; все принятые в знаменателе, включая незавершённые после deadline | transfers.jsonl, transfers.survey.json и summary.json; тест 7 быстрых/2 поздних/1 незавершённый даёт 70% |
| Confirmation 180 с, прогрев 30 с | Сохранённый профиль и originMs в JTL, когорта [30;180) | profile.properties; граничный тест удерживает позднее завершение в исходной когорте |
| Drain до 120 с, незавершённые сохранены | collect_transfers.py ограничивает весь опрос deadline, сохраняет PROCESSING/UNKNOWN | transfers.survey.json и каждая строка transfers.jsonl; потерянные данные делают вывод недоказанным |
| GET и метрики отдельно от бизнес-потока | JTL содержит POST; метрики в отдельных CSV/JSONL, статусы после подачи и HTTP-хвоста | Не прибавляются к actual_post_rps; httpRequests — вспомогательный накопительный счётчик |
| Отказы и ошибки отдельно | Классы accepted/application_rejection/overload_503/timeout/invalid_202/http_or_transport_error | categories в summary.json; unit-тесты классификации; COMPLETED/FAILED отдельно от принятия |
| При очереди >1000 вернуть 503 и Retry-After: 1, без создания/списания | JMX выделяет 503 и сохраняет retryAfter; метрики показывают очередь | Без достижения такой очереди основные прогоны эту ветвь не доказывают. Ветвь не входит в каталог F01–F18, и эталоны Java/Python/ручной её не проверяют; единственная функциональная проверка — регрессионный тест жюри `overloadReturns503WithRetryAfterAndDoesNotDebit` в `jury/stand-src`. Нагрузочный PASS этой ветви не приписывается |
| Достоверность измерений | Полные исходные файлы, приращения счётчиков, пропуски вместо нулей, проверка ID | tests/test_analysis.py, tests/test_collectors.py, повторный analyse.py; [независимый пересчёт Windows-повтора](evidence/independent-acceptance/windows-java25/recount.json) |
| Совместимость инструментария | Java 17/21; чистые окружения CPython 3.11–3.15 со smoke, анализом и PNG; Windows с ресурсами генератора через WinAPI | Матрица и Windows-повтор в отчёте: стенд на Java 25, генератор на Java 17. Не утверждает ВДИ, полное декартово произведение версий или генератор JMeter на Java 25 |
| Поведение при длительной подаче | stability 20 POST/с, измерение [60;600) | JTL, metrics.csv, графики и тренды отчёта; только десять минут, без вывода об отсутствии утечек |
