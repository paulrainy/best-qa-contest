# Границы выводов

Измерения относятся к учебному стенду с историей 30 000 переводов и выбранным профилем OTHER по 100,00 ₽. Промышленной статистики трафика нет; выводы не охватывают другие суммы, долю OWN, тарифные пороги и миллион записей. Функциональное покрытие остаётся задачей остальных эталонов.

Генератор и стенд работают на одном Mac ARM64. Конкуренция за CPU, память и диск влияет на результат. Миллисекунды и наблюдаемая пропускная способность не являются нормативом для компьютера участника. Проверка Java 21 и старших CPython подтверждает запуск инструментария, а не равную производительность разных сред.

Основные профили выполнены на Mac ARM64. 12.11.2026 smoke и confirmation повторены на Windows 11 AMD64 — слабом настольном ПК, а не на ВДИ: стенд на Java 25, генератор на Java 17 из комплекта JMeter. Для этого сбор ресурсов генератора в Windows переведён с ps на WinAPI из stdlib; CPU там — доля одного ядра за интервал между замерами, а не оценка ps. Java 25 не входит в объявленную пару 17/21: стенд на ней работает, а JMeter 5.6.3 с Groovy 3.0.20 не исполняет JSR223 этого JMX. Linux реального прогона не проходил. Целевой корпоративный ВДИ не проверялся; до объявления окружения финала повторить установку, smoke и confirmation на нём.

Метрики снимаются примерно раз в 5 секунд. Нулевая очередь в замерах не исключает коротких всплесков между ними. CPU стенда из JVM и CPU генератора из ps имеют разные базы и интервалы усреднения; складывать эти проценты нельзя. RSS генератора включает больше, чем его heap. Записанные ресурсы не заменяют отдельный профиль генератора на выделенной машине.

Десять минут stability позволяют оценить тренд на этом интервале. Они не подтверждают суточную устойчивость, отсутствие утечек, поведение после долгой эксплуатации или восстановление после аварий. Увеличение heap на коротком отрезке без анализа GC само по себе не доказывает утечку.

Предел производительности устанавливается только при наблюдаемой деградации и исключённом ограничении генератора. Успешные ступени до 50 POST/с задают проверенный диапазон, а не максимальную пропускную способность. Если очередь не превысила 1000, защита 503 при такой очереди нагрузочным прогоном не подтверждена; отсутствие 503 не является проверкой этой ветви.

SLO относится ко всем принятым операциям измерительной когорты, включая FAILED как финальный статус. Это не тождественно доле успешно выполненных переводов; COMPLETED, FAILED и отказы при приёме показываются отдельно. Исходные completedAt надёжнее времени позднего опроса, но зависят от корректности часов самого стенда. Сдвиг часов запрещён и проверяется до/после прогона.

Независимый повтор 12.11.2026 выполнила отдельная сессия агента на другом оборудовании и другой ОС (Windows 11 AMD64). Он проверяет воспроизводимость инструкции и расчётов, но не заменяет пилот на целевом ВДИ, прогон на Linux и проверку человеком-коллегой.
