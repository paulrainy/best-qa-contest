## Цель и границы

Проверяется целевой поток 50 новых POST/с: p95 принятого POST ≤500 мс и не менее 95% принятых переводов в финальном статусе за ≤2 с. Модель — 100% новых OTHER по 100,00 ₽ между разными активными клиентами, 2000 пар, история 30 000. Методика и формулы закреплены [до измерений](methodology.md); [прослеживаемость](traceability.md) показывает проверенные условия и оставшиеся ограничения.

Это проверка конкретного учебного сервиса на локальной машине. ВДИ, миллион записей, сутки эксплуатации и максимальная пропускная способность в объём не входят. Нагрузочный эталон не требует списка найденных дефектов и не назначает баллы.

## Окружение и воспроизведение

Mac16,6, Apple M4 Max, 14 логических CPU, 36 ГиБ RAM, macOS 27.2 ARM64. Генератор и стенд на одной машине. Базовые основные профили: Temurin 17.0.21+9, CPython 3.11.14, JMeter 5.6.3 без плагинов. Heap стенда и генератора: `-Xms256m -Xmx1g`. Стенд запускался из корня репозитория с `JAVA_HOME` на bundled JRE 17 и `JAVA_TOOL_OPTIONS='-Xms256m -Xmx1g'`; генератор отдельно использует `HEAP='-Xms256m -Xmx1g'`. Максимальный heap 1 ГиБ виден в сырых метриках.

Точные команды, версии, установленные пакеты и SHA-256 исходников находятся в environment.json каждого прогона. initial.json фиксирует history=30000, здоровье и RUNNING обоих потребителей. reset.json относится к единственному reset до подачи; после прогона записаны реальные часы и состояние потребителей. Reset не обнуляет накопительные счётчики процесса: для скорости используются их приращения.

Команда каждого запуска соответствует [README](README.md), с отдельным новым output. Рабочие каталоги `build/` не выдаются участникам. Отобранные исходные файлы копируются в evidence без редактирования; абсолютные пути в командах сохраняют фактическое происхождение. JTL и ответы API — первичные измерения, summary и PNG — производные. Детальный INFO-лог JMeter и служебный HTML основных прогонов остаются в build; для raw CLI сохранён самостоятельный HTML.

## Контроль достоверности

На отдельной копии JMX добавлена задержка dispatch 20 с перед HTTP: [wrapper](evidence/control/slow-dispatch-jmeter), [фактически загруженный JMX](evidence/control/slow-dispatch-control.jmx). Продуктовый JAR не менялся. Из 60 POST только 28 начались в [0;30): 0,93 POST/с вместо 2. Оставшиеся 32 начала сохраняются в JTL вне измерительной когорты. Анализ вернул load_valid=false, UNPROVEN, runner exit=2. Быстрый ответ сервиса при недодаче не объявлен подтверждением цели.

После удаления условия [штатный smoke](evidence/control/restored-smoke/summary.json) дал 60/60 принятых и завершённых переводов, ровно 2 POST/с, p95 12 мс, SLO 100%, полные метрики. Это проверка инструментария, не доказательство 50 POST/с. В исходном environment.json контроля jmxSha256 относится к каноническому входу wrapper; wrapper заменяет его отдельной копией перед запуском. Оба файла и их отдельные хеши сохраняются в манифесте evidence, поэтому изменённая копия не выдаётся за штатный JMX.

Самостоятельный [raw CLI](evidence/raw-cli/html/index.html) загрузил JMX в JMeter 5.6.3 и построил HTML: 60 samples, 0 ошибок. Низкоуровневый запуск не содержит полного набора статусов/метрик и не используется для SLO. Его расписание включает тот же HTTP-хвост 35 с; позднее добавленное штатное jmeterengine.force.system.exit ускоряет завершение CLI после теста, без изменения измерительных окон.

Тесты анализа и сборщиков: 17/17 на Mac; после доработки сбора ресурсов под Windows — 18/18 на Windows (новый тест интервального CPU выполняется только там). Покрыты полный nearest-rank p95, 7/10 вместо 7/9, классификация отказов, границы ступеней, поздняя финализация, пропуски/дубли статусов, смена сегмента накопительного счётчика, недодача и общий deadline опроса. Независимый ручной пересчёт smoke из JTL и сохранённых ответов API совпал: 60 уникальных ключей/ID, p95 12 мс, 60/60 в срок. [Повторный анализ](evidence/reanalysis-check.json) точно воспроизвёл значения всех 11 summary; [отдельный пересчёт](evidence/independent-recount.json) подтвердил количества, уникальные ключи/ID, p95 и SLO каждого окна этих 11 прогонов. После правок инструментов все 11 summary ещё раз пересчитаны на Windows и совпали: [author-reanalysis.json](evidence/independent-acceptance/windows-java25/author-reanalysis.json).

[Ошибка процесса](evidence/tool-guards/failed-process.json) проверена отдельным executable, завершающимся с 7: runner возвращает 1 и не создаёт summary. [Запрет перезаписи](evidence/tool-guards/existing-output.json) проверен отдельно: попытка использовать существующий output отклонена с exit=1 до запуска нагрузки, SHA-256 JTL остался прежним.

### Независимый повтор на Windows

12.11.2026 smoke и confirmation повторила отдельная сессия агента по README эталона: [заключение и доказательства](evidence/independent-acceptance/windows-java25/README.md). Окружение — Windows 11 AMD64, Pentium G4560 (2 ядра, 4 логических CPU), 12 ГиБ RAM; генератор и стенд на одной машине. Стенд работал на Java 25.0.5, генератор — на JRE 17.0.21 из комплекта JMeter, Python — 3.11.18 через uv.

| Прогон | POST / принято | Факт POST/с | p95, мс | В срок ≤2 с | Итог |
| --- | --- | --- | --- | --- | --- |
| smoke [0;30) | 60/60 | 2,00 | 124 | 100% | PASS, полные метрики и ресурсы генератора |
| confirmation [30;180) | 7440/7440 | 49,6 | 5 | 100% | **PASS**, 9000/9000 COMPLETED |
| raw CLI через `jmeter.bat` | 60/60, 0 ошибок | — | — | — | JMX загружен, HTML построен |

Отдельный пересчёт из JTL и статусов совпал с summary. Число POST в confirmation такое же, как у автора: 9000 всего, 7440 в окне. На холодном старте этой слабой машины первые 10 с дали p95 2401 мс и очередь учёта до 185; к 20-й секунде всё стабилизировалось. Измерительное окно [30;180) этот участок исключает по методике. Без исключения прогрева p95 всех POST составил бы 710 мс — это аргумент за обоснованный прогрев, а не дефект стенда.

Повтор выявил и закрыл проблемы инструментария под Windows: сбор ресурсов через `ps`, выбор JVM в `jmeter.bat`, `pause` при ошибке, остановку дерева процессов, кодировку вывода. JMeter 5.6.3 с Groovy 3.0.20 не исполняет JSR223 этого JMX на Java 25: прогон без единого POST runner отклоняет с кодом 1. Генератору нужна Java 17 или 21.

## Вывод и дальнейшие проверки

В базовом окружении подтверждены целевые p95 и SLO на 50 POST/с и наблюдаемая стабильность на 20 POST/с в течение десяти минут. Узкое место в диапазоне 10–50 POST/с не выявлено; максимальная пропускная способность не устанавливалась. Отказы при перегрузке не вызывались, поэтому эту ветвь нагрузочным экспериментом не подтвердили. [Ограничения](limitations.md) и [защита решений](defense.md) обязательны при интерпретации результата. При необходимости проверить предел расширять ступени отдельным экспериментом на выделенном генераторе; не подставлять заранее ожидаемый bottleneck. Независимый повтор на Windows подтвердил тот же вывод для confirmation на значительно более слабой машине. До официальной выдачи повторить smoke и confirmation на целевом ВДИ, с генератором на Java 17 или 21.

## Наблюдаемые признаки для будущей шкалы

Баллы и веса здесь не назначаются; признаки нужны для сопоставления четырёх направлений.

| Признак | Полноценное выполнение | Пример частичного выполнения |
| --- | --- | --- |
| Модель нагрузки | Открытая подача новых POST, интенсивность считается только по бизнес-операциям | Замкнутый цикл «создать → дождаться → создать» или служебные GET в RPS |
| Данные | Свои пары счетов, проверенный бюджет остатков и лимитов, reset до прогона | Поток прикладных отказов из-за исчерпанного лимита |
| Доказанная подача | Фактические начала POST сверены с целью в каждом окне, недодача делает вывод недоказанным | Вывод о сервисе без проверки, что генератор выдал цель |
| Популяции и расчёт | Когорта по началу POST, nearest-rank p95 полного массива, незавершённые в знаменателе SLO | Среднее оконных p95, потерянные незавершённые, прогрев внутри итога |
| Асинхронность | Финальный статус и `completedAt − createdAt` по каждому принятому ID | Только время HTTP-ответа 202 |
| Наблюдение | Очереди, приращения обработки, ресурсы стенда и генератора, пропуски не превращены в нули | Скриншот одного графика без исходных чисел |
| Воспроизводимость | Сырые JTL/метрики/статусы, профиль, окружение, повторный расчёт без стенда | Только HTML-отчёт JMeter |
| Честные выводы | Границы машины, длительности и профиля; отказ от утверждений, не подтверждённых данными | «Система выдерживает прод» по десятиминутному локальному прогону |
