# Контроль чувствительности проверки HALF_UP

Ревью первоначального состава63 выявило пробел:3456,78×1%=34,5678 округляется до34,57 и в HALF_UP, и в HALF_EVEN. Добавлен вариант3000,50×1%=30,005→**30,01**; HALF_EVEN дал бы30,00.

`half_even_observation.py` — временный pytest-плагин только для этого контроля. Он меняет **наблюдаемое декодированное значение**30,01 на30,00 для суммы3000,50. Готовый JAR, БД, проводки и фактическая комиссия стенда не изменяются. Плагин не подключён к обычному проекту и не входит в participant.

- `old-set-ready/results.xml`, `old-set-ready.log`: прежние63 варианта с тем же плагином проходят. В нынешнем исходнике новый случай исключён **только для доказательства пробела** через `--deselect`; это не полный принимаемый прогон актуального эталона.
- `new-detects/results.xml`, `new-detects.log`: новый случай с плагином падает на30,00≠30,01. Это ожидаемый отрицательный контроль, не дефект стенда.
- `correct-stand/results.xml`: без плагина весь проект, включая11 unit-тестов, проходит75/75. Этот объединённый XML не передаётся анализатору интеграционного состава.
- Все10 актуальных полных64-case прогонов без плагина — в [final/](../final/), там же отдельно11 unit-проверок каждой комбинации.

Контроль выполнялся только автором после независимого ревью. Независимые XML остаются63-case, их нельзя выдавать за повтор усиленного набора.
