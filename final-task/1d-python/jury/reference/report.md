11.11.2026. Реализован самостоятельный проект pytest по ТЗ2.0 и F01–F18. Бизнес-ожидания десятичные, API передаёт деньги числом; AMQP и PostgreSQL проверяются на реальном готовом стенде. Стенд в ходе Python-плана не менялся. Независимая приёмка первоначального набора 63 пройдена. ## Проверка данных и диагностики

Дополнительный итоговый авторский прогон 3.11/Java 21 —64 PASS: [XML](evidence/final-author-sql/full/results.xml), [HTTP](evidence/final-author-sql/http.jsonl). По его собственным 127 счетам и 49 принятым переводам выполнена [SQL-сверка](evidence/final-author-sql/sql.json): остаток равен сумме проводок; COMPLETED имеет ровно один кредит суммы, FAILED — ровно один полный возврат суммы+комиссии без кредита получателю. Нарушений 0. Сверка не включает чужие переводы или всю историю стенда.

Контроли воспроизводимости — [controls.json](evidence/final-author-sql/controls.json):

- недоступный PostgreSQL-порт даёт setup ERROR, pytest1 и явную причину «БД недоступна»; ошибка не считается продуктовым дефектом;
- существующий путь XML отклоняется до запуска: pytest4, старый файл не изменён;
- анализатор отклоняет отсутствие теста, failure, error/timeout, skip, дубликат и пустой каталог; полный зелёный XML принимает;
- после исключения в глобальном сценарии восстановлены часы/оба потребителя, закрыты PostgreSQL и AMQP; это проверено реальным `test_scope_restores_after_exception_and_connections_close` во всех 10 прогонах;
- итоговый контроль после диагностики — COMPLETED, остатки 999900/100, реальные часы и оба RUNNING: [HTTP](evidence/final-author-sql/final-control-http.jsonl).

## Независимая приёмка и закрытие замечания

[Независимый отчёт](evidence/independent/report.md) относится к d47e461 и 63 интеграционным проверкам. Свежий локальный clone с 48 настоящими LFS-объектами, новая `.venv`, Python3.11.14/Java 21:11 помощников и два полных прогона по 63 PASS, оба анализатора 0. Повтор после недоступной БД/старых отчётов выполнен без reset в другом порядке; часы/потребители восстановлены, собственный процесс остановлен. Независимо проверены прежние 10 матричных XML, хеши и SQL-снимок 125/47. Это не проверка внешней доставки GitHub или установки без общего пакетного кэша.

Ревью: Critical0, Important0, одно замечание M1 к покрытию округления. Исполнитель оценил его как требующее закрытия до завершения эталона: прежний пример 34,5678→34,57 пропускает ошибочный HALF_EVEN. Добавлен 3000,50→30,005→30,01, с точными остатками 896969,49/103000,50. Временный плагин менял только наблюдаемое API-значение комиссии на 30,00; стенд и реальные деньги не изменялись. Прежние 63 варианта не обнаружили подмену, новый вариант упал 30,00≠30,01; без плагина весь проект 75/75 PASS. [Контроль чувствительности](evidence/tie-control/README.md).

После исправления все 10 полных прогонов матрицы повторены:64 PASS и 11 помощников в каждой комбинации. Итоговый повтор без reset в случайном порядке seed20261111 дал 64 PASS ([лог](evidence/final/random.log), [анализатор](evidence/final/random-check.txt)); весь проект после этого —75 PASS ([лог](evidence/final/whole-project.log)). Точный каталог обновлён одним новым ID, SQL/отрицательные контроли повторены на итоговой версии. Второе независимое ревью не проводилось; прежний отчёт не переименован в проверку 64 случаев. ## Соответствие и границы

[Трассировка](traceability.md) покрывает все 18 общих групп на глубине Java и ручного решения. Дополнительные проверки верхней границы комиссии, MF01 и точной половины копейки дают 64 интеграционных testcase вместо 61 в Java; это не требование к количеству тестов участника. Вспомогательные 11 unit-проверок отделены от каталога полного интеграционного набора. Нет skip/xfail, известных допустимых падений, прямой записи в БД, чтения внутренних классов стенда или подмены JAR.

Для одновременных BLOCKED/CLOSED принимается один из применимых 422-кодов: ТЗ не задаёт приоритет. Адресат уведомления проверяется URL клиента и SQL, не неописанным полем clientId в JSON. Общая роль `qa` и запрет записи на стороне сервера ранее проверены общими средствами; Python-клиент дополнительно не отправляет SQL кроме SELECT. [Открытые риски](known-findings.md).

Windows/ВДИ AMD64, производительность/НФТ, гонки, повторная доставка, три попытки/DLQ, инфраструктурные отказы и длительная эксплуатация этим проектом не подтверждены. Нагрузочный план отложен пользователем; он не выполнялся. Намеренные дефекты не внедрялись, балльная шкала не создавалась.

Для будущей шкалы наблюдаемы: связь требования с реальной проверкой, независимые данные, проверка денег/проводок вместо одного HTTP-кода, собственное AMQP-событие, ограниченные ожидания, cleanup при ошибке, повторяемая установка и честный отчёт. Частично выполненный проект можно различать по этим результатам; веса и штрафы требуют отдельного согласования после четырёх эталонов.
