# Python-эталон автоматизации сервиса переводов

Проект только для жюри. Требования — [каноническое ТЗ](../../../jury/source/spec.md), объём — [F01–F18](../../../jury/coverage-catalog.md). Участник создаёт собственный проект и не обязан повторять эти библиотеки или структуру.

## Подготовка

На выделенном стенде запустите готовую [Python-выдачу](../../participant/README.md) с Java17 или21. Исходники и Maven не нужны. Одновременно не запускайте другие эталоны: сценарии меняют общие часы и состояние потребителей.

Для проекта нужны CPython3.11 или старше, uv и доступ к сети только для установки зависимостей. Из этого каталога:

```bash
uv sync --locked --python 3.11
uv run --locked --python 3.11 python --version
uv run --locked --python 3.11 pytest --collect-only -q
```

Адреса и тестовые логины находятся в [config/stand.ini](config/stand.ini). Можно передать другой INI через `--stand-config /путь/stand.ini`; это позволяет проверить диагностику недоступного подключения. БД подключается по PostgreSQL без SSL, только SELECT; брокер — AMQP0-9-1. Установка проекта, соединение со стендом и assertion теста — разные причины неуспеха, они не маскируются.

## Исполнение

Один reset допустим **до** полного прогона. Сначала убедитесь, что стендом не пользуются другие исполнители:

```bash
curl -f -X POST http://localhost:18400/api/test/reset
uv run --locked --python 3.11 pytest tests_support -q
uv run --locked --python 3.11 pytest tests --junitxml=build/full/full.xml &&
uv run --locked --python 3.11 python ../../../jury/tools/check_reference_results.py python build/full
```

Используйте новый каталог XML для каждого запуска. Анализатор сверяет точный состав интеграционных проверок и отвергает failure/error/skip, отсутствие теста и повторный результат. XML вспомогательных unit-тестов сохраняется отдельно. Для повторного полного прогона reset не нужен: тесты создают собственные счета. Параллельный pytest не поддерживается; глобальные сценарии всегда восстанавливают часы и потребителей через `finally`.

Уже существующие пути `--junitxml` и `--http-log` отклоняются до запуска, чтобы старый результат не выглядел новым. Сначала проверьте код завершения pytest, затем вызывайте анализатор через `&&`. Сам анализатор проверяет содержимое XML, а не дату его создания. `--http-log build/новый-прогон/http.jsonl` сохраняет реальные запросы/ответы; `--order-seed 20261111` перемешивает весь набор без исключения проверок.

Для старшего интерпретатора укажите его в **обеих** командах:

```bash
uv sync --locked --python 3.15
uv run --locked --python 3.15 python --version
uv run --locked --python 3.15 pytest tests --junitxml=build/python315/full.xml
```

`.python-version` задаёт3.11 по умолчанию; `--python` выбирает другой интерпретатор. Один `uv.lock` применяется ко всей проверяемой матрице; верхней границы Python нет. Фактически проверенные версии и ограничения будут зафиксированы в отчёте при завершении приёмки. Работа на macOS ARM64 сама по себе не подтверждает Windows/ВДИ AMD64.
