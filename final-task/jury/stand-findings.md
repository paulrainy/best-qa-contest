## Исправления по ревью 12.11.2026

Ревью всех финальных заданий нашло ненамеренные отклонения стенда. Все они исправлены, четыре выдачи пересобраны на Temurin JDK 17.0.21+9. Актуальный JAR — `220d02c815017de6b22c2d3f16c6b97a1495279c1ae9c5a8029d4f3a8be0f5a2`, [сводка и доказательства](verify/evidence/2026-11-12-review-fixes/README.md).

| Отклонение | Исправленное поведение | Регресс |
| --- | --- | --- |
| Уведомления без правила трёх обработок (ТЗ, раздел 8): некорректное сообщение сразу уходило в DLQ, сбой БД оставлял сообщение без ack/nack, событие без `transferId` обходило защиту от повтора | Единое правило учёта и уведомлений: три обработки подряд, затем DLQ; сбой БД — повтор; событие без корректного `transferId` некорректно | `notificationFailureIsRetriedThreeTimesThenDlqWithoutBlocking` |
| Событие публиковалось после commit без защиты: при сбое публикации принятый перевод навсегда оставался PROCESSING, а API отвечал 500 | Событие зафиксированной операции откладывается в памяти процесса и повторяется; закрытый канал публикации открывается заново | `eventOfCommittedTransferIsDeferredWhenPublishFails` |
| HTTP API слушал все сетевые интерфейсы, брокер и H2 — только локальные | HTTP на 127.0.0.1 и ::1 | `httpListensOnlyOnLoopback` |
| Отчёт об обороте брал дату завершения в часовом поясе JVM, а не МСК. Найдено при приёмке на Windows в UTC−6: перевод в 00:01 МСК попадал в предыдущие сутки | Границы суток МСК считаются явно | `turnoverUsesMoscowCompletionDateInNonMoscowJvm`; весь регресс стенда идёт в поясе America/Guatemala |

Отсутствие заложенных дефектов не означает завершённый аудит всех требований.
