# Исправления по ревью финальных заданий

12.11.2026, Windows 11 Pro 10.0.26200 AMD64, часовой пояс машины — Central America Standard Time (UTC−6). Ревью всех финальных заданий дало 15 находок. По решению пользователя исправлены все, в том числе в коде стенда. Стенд пересобран тем же Temurin JDK 17.0.21+9 (`openjdk version "17.0.21" 2026-10-20`), что и прежний JAR. JDK скачан с GitHub Adoptium, SHA-256 архива совпал с опубликованным. Новый SHA-256 всех четырёх готовых JAR — `220d02c815017de6b22c2d3f16c6b97a1495279c1ae9c5a8029d4f3a8be0f5a2`. Контракт ТЗ v2.0 и каталог F01–F18 не менялись.

В текстовых логах Maven удалены конечные пробелы строк; XML, JSON и журналы HTTP не редактировались.

## Что изменено в стенде

- **Уведомления.** Работает правило трёх обработок подряд, затем DLQ (ТЗ, раздел 8), общее с учётом. Раньше некорректное сообщение сразу уходило в DLQ, сбой БД оставлял сообщение без ack/nack и занимал prefetch, а событие без `transferId` обходило защиту от повторного уведомления.
- **Публикация после commit.** Если публикация не удалась, событие зафиксированной операции откладывается в памяти процесса и повторяется раз в 500 мс; закрытый канал открывается заново. Раньше перевод оставался PROCESSING навсегда, API отвечал 500 при уже списанных деньгах, а учёт терял TransferCompleted/TransferFailed.
- **HTTP API.** Слушает 127.0.0.1 и ::1, как брокер и H2 слушают локальные адреса. Раньше были открыты все интерфейсы.
- **Отчёт об обороте.** Новое отклонение, найдено при этой приёмке. `CAST(completed_at AT TIME ZONE 'Europe/Moscow' AS DATE)` в H2 берёт часовой пояс JVM. На машине в UTC−6 перевод, завершённый в 00:01 МСК, попадал в предыдущие сутки, и Java-эталон `TurnoverTest` падал. На Mac автора с поясом МСК дефект не проявлялся. Теперь границы суток МСК считаются явно. Та же правка внесена в С7 `jury/sql/reconciliation.sql`, а к SQL07 ручного эталона добавлено замечание.
- **Регресс стенда.** Фиксированные паузы заменены барьером из маркерного перевода. Весь набор идёт с `-Duser.timezone=America/Guatemala`, чтобы правила суток МСК проверялись не только на машине в МСК.

## Границы

- Все прогоны выполнены в этой сессии исполнителем исправлений. Отдельной независимой проверки этого хеша нет.
- Java 21 на машине нет, поэтому на новом JAR она не проверялась. Матрица CPython 3.12–3.15 не повторялась.
- Полный ручной набор из 18 групп и независимая ручная выборка заново не выполнялись: адресный повтор не выдаётся за такой прогон.
- Пилот на ВДИ по-прежнему не выполнен.
- Отложенная публикация живёт в памяти процесса. Стенд и так хранит всё в памяти, после перезапуска данные начинаются заново.
- Удаление обменника из консоли брокера не делает публикацию ошибкой. Такую поломку по-прежнему лечит reset.
