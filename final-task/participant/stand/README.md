# Стенд «Сервис переводов»

Стенд — готовая сборка сервиса из ТЗ (`../spec.md`): API, брокер сообщений, учёт, уведомления и БД в одном процессе. Ничего устанавливать не нужно, нужна только Java 17 или новее. Данные живут в памяти: после перезапуска стенд начинает с чистого листа.

## Запуск

Windows — `run.cmd`, Linux и macOS — `run.sh`. Или из этой папки:

```
java -jar transfer-stand.jar
```

Через 10–20 секунд в консоли появится «Стенд готов» и список адресов. Остановить — Ctrl+C. Если порт занят, поменяйте его в `stand.properties`.

## Что доступно

| Что | Адрес | Логин / пароль |
| --- | --- | --- |
| HTTP API | `http://localhost:18400/api/v1/...` | — |
| Брокер, AMQP 0-9-1 (клиенты RabbitMQ: `amqp-client`, `pika`, плагины JMeter) | `amqp://localhost:5672/`, виртуальный хост `/` | `guest` / `guest` |
| Веб-консоль брокера: очереди, обменники, сообщения | `http://localhost:15672/` | `guest` / `guest` |
| БД, драйвер H2 (DBeaver, JDBC) | `jdbc:h2:tcp://localhost:19400/mem:stand` | `qa` / `qa` |
| БД, протокол PostgreSQL (psycopg, драйвер PostgreSQL) | `localhost:19402`, база `stand`, SSL выключен | `qa` / `qa` |
| Веб-консоль H2 | `http://localhost:19401/` (в поле JDBC URL — адрес БД выше) | `qa` / `qa` |
| Метрики в формате Prometheus | `http://localhost:18400/metrics` | — |

Брокер совместим с RabbitMQ по протоколу AMQP 0-9-1, но это не RabbitMQ: веб-консоль выглядит по-другому. Права в брокере полные: можно создавать свои очереди, привязывать их к обменнику `transfers`, читать и публиковать сообщения. БД — только на чтение.

Таблицы БД: `clients`, `accounts`, `transfers`, `postings` (проводки), `notifications`.

## Тестовые данные

При старте стенд создаёт:

- 2000 клиентов `C00001`–`C02000`, у каждого два активных счёта: `40817810` + номер клиента × 10 + 1 или + 2, например `40817810000000000011` и `40817810000000000012` у `C00001`;
- историю переводов этих клиентов за прошлые месяцы;
- клиентов `C02001`–`C02005`, у которых второй счёт заблокирован или закрыт.

Список всех счетов — `test-data/accounts.csv` рядом со стендом (создаётся при запуске) или `GET /api/test/accounts.csv`.

Для своих сценариев удобнее заводить новых клиентов и счета через тестовый API: у них нет истории.

## Тестовый API

Это не часть продукта из ТЗ, а инструменты стенда. Дефектов в нём нет.

| Метод | Путь | Что делает |
| --- | --- | --- |
| `POST` | `/api/test/reset` | Сбросить стенд: пересоздать данные, очистить очереди, вернуть часы |
| `POST` | `/api/test/accounts` | Создать счёт. Тело: `{"balance": 1000.00, "status": "ACTIVE", "clientId": "C00001"}`; все поля необязательны. Без `clientId` создаётся новый клиент, его можно назвать полем `fullName` |
| `PUT` | `/api/test/accounts/{accountNumber}/status` | Сменить статус счёта. Тело: `{"status": "CLOSED"}` |
| `GET` / `PUT` / `DELETE` | `/api/test/clock` | Часы стенда. `PUT {"now": "2027-03-15T23:59:00+03:00"}` переводит часы, дальше время идёт как обычно; `DELETE` возвращает реальное время |
| `GET` | `/api/test/consumers` | Состояние потребителей `accounting` (учёт) и `notifications` |
| `POST` | `/api/test/consumers/{accounting\|notifications}/pause` | Приостановить потребителя: сообщения копятся в очереди |
| `POST` | `/api/test/consumers/{accounting\|notifications}/resume` | Возобновить потребителя |
| `GET` | `/api/test/accounts.csv` | Все счета в CSV |
| `GET` | `/api/v1/health` | Стенд жив; текущее время стенда |

## Правила

- Стенд — чёрный ящик. Декомпилировать, распаковывать и изучать код `transfer-stand.jar` и подменять его библиотеки запрещено. Находки, полученные так, не засчитываются.
- Если стенд «сломался» — вызовите `POST /api/test/reset` или перезапустите его.
