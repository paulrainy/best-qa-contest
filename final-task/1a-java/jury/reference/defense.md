# Защита Java-проекта: 7 минут + 3 минуты вопросов

1. **0:00–1:00 — задача и риски.** Построено тестирование с нуля: денежные правила, идемпотентность, асинхронный финал и наблюдение. Полнота показана трассировкой F01–F18, не количеством найденных ошибок.
2. **1:00–2:00 — устройство.** Самостоятельный Maven-проект, настройки вне тестов, transport helpers отдельно от assertions, собственные данные, BigDecimal, SELECT и ограниченные ожидания по transferId.
3. **2:00–3:30 — воспроизводимость.** Запуск готового стенда; полный зелёный набор и XML-анализатор. Java 17/21, повтор и случайный порядок. Показать версии и хеш, а не пересказывать все тесты.
4. **3:30–5:00 — два результата.** F10: комиссия 100 с превышения порога. F16: полный возврат 40400 при FAILED. Открыть методы и свежие XML; показать сверку денег и отсутствие исключений для падений.
5. **5:00–6:00 — устойчивость проверки.** Подписка до действия, закрытие очереди, восстановление часов и потребителей после исключения, отсутствие reset внутри сценариев. Контрольная поломка должна сломать обычный тест.
6. **6:00–7:00 — вывод и границы.** Намеренные дефекты сняты, функциональный результат оценивается по полному зелёному регрессу. Нагрузка, эксплуатационная надёжность и Windows/ВДИ требуют соответствующих проверок. Локальный функциональный прогон не доказывает производительность ВДИ.

Вопросы для обсуждения: как отличить ошибку оракула от продукта; почему JSON number и BigDecimal совместимы; зачем проверять проводки и остатки вместе; что происходит при повторном событии; почему FAILED не занимает лимит; почему зелёный частичный набор не заменяет полный. Ответы должны опираться на ТЗ и фактические результаты, не на скрытые исходники стенда.
