# Эталон автоматизации на Java

Материал жюри. Самостоятельный Maven-проект по контракту выдачи, созданный без стартового проекта участника. 61 исполняемая проверка покрывает F01–F18: HTTP, AMQP, SQL, границы, статусы, время, идемпотентность и асинхронность. [Трассировка](traceability.md), [отчёт](report.md), [известные отклонения](known-findings.md), [защита](defense.md).

## Среда

Полный JDK 17 и Maven 3.9+; проект также проверяется на JDK 21, целевой байткод — 17. Для стенда достаточно Java 17/21 соответствующей ОС/архитектуры. Maven скачивает закреплённые зависимости при первом запуске в локальную `.m2/` проекта; эта установка требует сети. Готовый стенд запускается без сети и Maven.

Стенд должен быть выделен этому прогону: все тесты последовательны, внешние запросы могут изменить результат. Настройки — `src/test/resources/stand.properties`. Порты и учётные данные можно переопределить файлом `-Dstand.config=/абсолютный/путь/stand.properties` или свойствами `-Dapi.url=...`, `-Ddb.url=...`, `-Damqp.uri=...`; файл конфигурации должен использовать те же ключи. Кеши, target и логи не входят в эталон.

## Воспроизведение

Из корня репозитория в первом терминале, выбрав Java через `JAVA_HOME`:

```bash
bash final-task/1a-java/participant/stand/run.sh
```

Дождаться «Стенд готов» и `GET http://localhost:18400/api/v1/health` → `UP`. Во втором терминале:

```bash
# Один общий сброс перед прогоном; команда удаляет предыдущие данные стенда.
curl -X POST http://localhost:18400/api/test/reset
cd final-task/1a-java/jury/reference
mvn test
# Ожидается код 0: 61 успешная проверка, 0 failures/errors/skipped.
python3 ../../../jury/tools/check_reference_results.py java target/surefire-reports
# Ожидается код 0: точный полный состав и отсутствие падений.
```

Все проверки требуют корректного поведения по ТЗ. Намеренные дефекты удалены; F10/F16 входят в полный зелёный набор. Анализатор отвергает любой failure/error/skip, в том числе прежние KNOWN assertions и ошибки очистки, а также неполный или повторяющийся состав.

Полный повтор в другом порядке:

```bash
mvn test -Dtest.order=random -Dsurefire.runOrder.random.seed=20261110
```

Тесты создают собственные счета и клиентов, не делают глобальных reset внутри набора. Сценарии времени/паузы используют `GlobalStandScope` и восстанавливают настройки в `close()` даже после assertion. Оборот получает две ещё не использованные соседние даты. Повтор полного набора допустим и без reset между запусками; для независимой приёмки начинать со свежего стенда.

Для проверки JDK 21 остановить стенд, выбрать JDK 21 через `JAVA_HOME`, запустить **тот же** JAR и повторить полный прогон. Не сравнивать задержки разных JVM как критерий функциональной совместимости.

## Организация проекта

- `support/`: настройки, transport helpers, собственные данные, ограниченные ожидания, закрытие AMQP/SQL, восстановление глобальных настроек.
- `*Test.java`: бизнес-проверки, ожидаемые результаты по ТЗ, `BigDecimal`, параметризация, запросы SELECT по собственным идентификаторам.
- `SupportTest`: проверка таймаутов, жизненного цикла временной очереди и восстановления после исключения на реальных локальных ресурсах.
- `evidence/`: отобранные XML и фактические результаты. Maven очищает только `target/surefire-reports` перед каждым запуском; частичный прогон не дополняется старыми результатами. не подменять его сохранёнными XML.

Перед защитой проверить версии, хеш стенда и состав результатов, описать ограничения окружения. Число тестовых методов, библиотек и найденных ошибок не является шкалой оценки участника.
