# Финал «Сервис переводов» — Java: автоматизация с нуля

## Задание

Создайте самостоятельный Maven-проект автоматизации на Java: проверки HTTP API, события AMQP и сверка данных SQL. Базовая версия Java 17, проект должен запускаться и на Java 21; целевой байткод 17. Подготовьте свои настройки, данные, ожидания и диагностику.

Цель — построить тестирование проекта с нуля по [ТЗ](spec.md), обосновать покрытие и показать реальные результаты. Расхождения со спецификацией оформляйте с шагами и доказательствами; количество находок не является целью. Готовый тестовый проект не выдаётся. UI, Docker, Kafka, внешний RabbitMQ и сервер Grafana не обязательны.

## Что сдать и защитить

Исходники проекта, pom.xml с закреплёнными зависимостями, README запуска, трассировка требований к тестам, результаты полных прогонов, SQL-сверки с результатом, отчёт и тезисы защиты.

В отчёте укажите окружение, версии, команды, покрытие, фактические результаты, ограничения и обоснованный вывод о готовности сервиса. Не подменяйте ожидаемый результат ошибочным поведением стенда. Инструкции и объяснения оформляйте в Markdown; код, конфигурация, исходные измерения и доказательства сохраняют необходимые форматы.

Сдать архив куратору не позднее пяти рабочих дней до финала, тема «Финал. Лучший тестировщик. ФИО». Защита — 7 минут, вопросы — 3 минуты. Работа индивидуальная, разрешены любые инструменты, включая нейросети; за результаты и ответы отвечает участник. Уточнения по условию передаются всем финалистам через куратора.

## Готовый стенд

Стенд — готовая сборка сервиса из ТЗ ([spec.md](spec.md)): API, брокер сообщений, учёт, уведомления и БД в одном процессе. Для запуска нужна только Java 17 или Java 21. Данные живут в памяти: после перезапуска стенд начинает с чистого листа.

## Запуск готового стенда

Windows — `stand/run.cmd`, Linux и macOS — `bash stand/run.sh`. Команды ниже выполняются из `stand/`:

```
java -jar transfer-stand.jar
```

Через 10–20 секунд в консоли появится «Стенд готов» и список адресов. Остановить — Ctrl+C. Если порт занят, поменяйте его в `stand/stand.properties`. Launcher использует `JAVA_HOME`, если он задан, иначе `java` из PATH. Java должна соответствовать ОС и процессору: macOS ARM64, Windows/Linux AMD64 и т. д.; JAR один для всех. Maven и сеть для запуска не нужны. При получении через Git установите Git LFS, один раз выполните `git lfs install --local`, затем `git lfs pull`, если вместо бинарников скачаны указатели. Одновременно запускайте только один экземпляр на стандартных портах.

## Что доступно

| Что | Адрес | Логин / пароль |
| --- | --- | --- |
| HTTP API | `http://localhost:18400/api/v1/...` | — |
| Брокер, AMQP 0-9-1 (клиенты RabbitMQ: `amqp-client`, `pika`, плагины JMeter) | `amqp://localhost:5672/`, виртуальный хост `/` | `guest` / `guest` |
| Веб-консоль брокера: очереди, обменники, сообщения | `http://localhost:15672/` | `guest` / `guest` |
| БД, драйвер H2 (DBeaver, JDBC) | `jdbc:h2:tcp://localhost:19400/mem:stand` | `qa` / `qa` |
| БД, протокол PostgreSQL (psycopg, драйвер PostgreSQL) | `localhost:19402`, база `stand`, SSL выключен | `qa` / `qa` |
| Веб-консоль H2 | `http://localhost:19401/` (в поле JDBC URL — адрес БД выше) | `qa` / `qa` |
| Метрики в формате Prometheus | `http://localhost:18400/metrics` | — |

Брокер совместим с RabbitMQ по протоколу AMQP 0-9-1, но это не RabbitMQ: веб-консоль выглядит по-другому. Права в брокере полные: можно создавать свои очереди, привязывать их к обменнику `transfers`, читать и публиковать сообщения. БД — только на чтение.

Таблицы БД: `clients`, `accounts`, `transfers`, `postings` (проводки), `notifications`.

## Тестовые данные

При старте стенд создаёт:

- 2000 клиентов `C00001`–`C02000`, у каждого два активных счёта: `40817810` + номер клиента × 10 + 1 или + 2, например `40817810000000000011` и `40817810000000000012` у `C00001`;
- историю переводов этих клиентов за прошлые месяцы;
- клиентов `C02001`–`C02005`, у которых второй счёт заблокирован или закрыт.

Список всех счетов — `test-data/accounts.csv` рядом со стендом (создаётся при запуске) или `GET /api/test/accounts.csv`.

Для независимости сценариев рекомендуется заводить новых клиентов и счета через тестовый API: у них нет истории.

## Тестовый API

Это не часть продукта из ТЗ, а инструменты стенда. Дефектов в нём нет.

| Метод | Путь | Что делает |
| --- | --- | --- |
| `POST` | `/api/test/reset` | Сбросить стенд: пересоздать данные, очистить очереди, вернуть часы |
| `POST` | `/api/test/accounts` | Создать счёт. Тело: `{"balance": 1000.00, "status": "ACTIVE", "clientId": "C00001"}`; все поля необязательны. Без `clientId` создаётся новый клиент, его можно назвать полем `fullName` |
| `PUT` | `/api/test/accounts/{accountNumber}/status` | Сменить статус счёта. Тело: `{"status": "CLOSED"}` |
| `GET` / `PUT` / `DELETE` | `/api/test/clock` | Часы стенда. `PUT {"now": "2027-03-15T23:59:00+03:00"}` переводит часы, дальше время идёт как обычно; `DELETE` возвращает реальное время |
| `GET` | `/api/test/consumers` | Состояние потребителей `accounting` (учёт) и `notifications` |
| `POST` | `/api/test/consumers/{accounting\|notifications}/pause` | Приостановить потребителя: сообщения копятся в очереди |
| `POST` | `/api/test/consumers/{accounting\|notifications}/resume` | Возобновить потребителя |
| `GET` | `/api/test/accounts.csv` | Все счета в CSV |
| `GET` | `/api/v1/health` | Стенд жив; текущее время стенда |

## Правила

- Стенд — чёрный ящик. Декомпилировать, распаковывать и изучать код `transfer-stand.jar` и подменять его библиотеки запрещено.
- Если стенд «сломался» — вызовите `POST /api/test/reset` или перезапустите его.

## Справка для собственного проекта

Контракт API, ошибок, событий и схема таблиц находятся в [ТЗ, разделы 8–12](spec.md#8-события). Для AMQP создайте временную очередь и привяжите её к `transfers` **до** отправки запроса; фильтруйте по своему `transferId`, ограничивайте ожидание таймаутом, закрывайте соединения. Не читайте рабочую очередь учёта вместо собственной подписки. Для БД используйте SELECT с параметрами и соответствующий драйвер H2 2.5.252 либо PostgreSQL. Деньги сравнивайте десятично (BigDecimal/Decimal), а не двоичной арифметикой.

Обычные сценарии создают собственные счета и клиентов. Один reset до полного прогона допустим; он удаляет данные всех сценариев. Изменение часов, паузы потребителей и глобальный оборот требуют выделенного стенда и последовательного исполнения; всегда восстанавливайте настройки. Время после перевода часов продолжает идти. Локальный запуск на Mac не подтверждает работоспособность и НФТ на целевом Windows/ВДИ.
