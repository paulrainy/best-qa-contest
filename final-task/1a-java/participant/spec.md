# ТЗ: сервис переводов между счетами

Версия 2.0. Сервис принимает от клиентских каналов переводы между рублёвыми счетами физических лиц, ведёт лимиты и комиссию, а зачисление и уведомления выполняет асинхронно через брокер сообщений.

Термины:

- **Клиент** — физическое лицо, владелец одного или нескольких счетов.
- **Перевод** — операция списания со счёта отправителя и зачисления на счёт получателя.
- **Московское время (МСК)** — UTC+3. Все даты и границы суток в ТЗ — по МСК.

## 1. Компоненты

| Компонент | Что делает |
| --- | --- |
| API переводов | Принимает перевод, проверяет правила, списывает деньги, публикует событие `TransferCreated` |
| Учёт | Читает `TransferCreated`, зачисляет деньги получателю, публикует `TransferCompleted` или `TransferFailed` |
| Уведомления | Читает `TransferCompleted` и `TransferFailed`, формирует уведомление отправителю |
| Брокер сообщений | RabbitMQ-совместимый брокер (AMQP 0-9-1) |
| БД | Клиенты, счета, переводы, проводки, уведомления |

## 2. Счета

Номер счёта — 20 цифр. Валюта — рубли.

| Статус | Списание | Зачисление |
| --- | --- | --- |
| `ACTIVE` | Разрешено | Разрешено |
| `BLOCKED` | Запрещено | Разрешено |
| `CLOSED` | Запрещено | Запрещено |

## 3. Перевод

### 3.1. Виды переводов

- `OWN` — со счёта на счёт того же клиента;
- `OTHER` — на счёт другого клиента.

Вид определяется автоматически по владельцам счетов.

### 3.2. Сумма

Сумма перевода — от 10,00 до 300 000,00 ₽ включительно, не более двух знаков после запятой.

### 3.3. Проверки при создании

Перевод отклоняется, если:

- счёт отправителя или получателя не найден;
- номера счетов отправителя и получателя совпадают;
- статус счёта не позволяет списание или зачисление (раздел 2);
- превышен дневной лимит (раздел 4);
- на счёте отправителя недостаточно средств для суммы перевода вместе с комиссией.

### 3.4. Жизненный цикл

1. API проверяет перевод, списывает со счёта отправителя сумму и комиссию и создаёт перевод в статусе `PROCESSING`. Списание и создание выполняются атомарно: остаток счёта никогда не становится отрицательным.
2. API публикует событие `TransferCreated`.
3. Учёт зачисляет получателю сумму перевода, переводит перевод в `COMPLETED` и публикует `TransferCompleted`.
4. Если к моменту зачисления счёт получателя закрыт, учёт переводит перевод в `FAILED` с причиной `RECIPIENT_ACCOUNT_CLOSED`, возвращает отправителю всю списанную сумму — перевод и комиссию — и публикует `TransferFailed`.

На каждое движение денег создаётся проводка. Остаток счёта всегда равен сумме его проводок: зачисления минус списания.

## 4. Дневной лимит

Сумма переводов `OTHER` одного клиента за календарные сутки (с 00:00:00 до 23:59:59 МСК) не может превышать 150 000,00 ₽. Учитываются переводы в статусах `PROCESSING` и `COMPLETED`, переводы `FAILED` лимит не занимают. Перевод проходит, если вместе с уже использованной суммой он не превышает лимит. Переводы `OWN` не ограничены.

## 5. Комиссия

- Переводы `OWN` — без комиссии.
- Переводы `OTHER` бесплатны, пока сумма таких переводов клиента за месяц не превышает 100 000,00 ₽. Учитываются переводы в статусах `PROCESSING` и `COMPLETED`.
- С части перевода сверх бесплатного порога взимается 1 %, но не менее 30,00 ₽ и не более 1 500,00 ₽.
- Комиссия округляется до копейки по математическим правилам: 0,005 и больше — вверх.

Пример: клиент уже перевёл другим клиентам в этом месяце 90 000,00 ₽ и переводит ещё 20 000,00 ₽. Сверх порога — 10 000,00 ₽, комиссия — 1 % от 10 000,00 = 100,00 ₽. Со счёта списывается 20 100,00 ₽.

Комиссия фиксируется при создании перевода и в дальнейшем не пересчитывается.

## 6. Идемпотентность

Каждый запрос на перевод содержит заголовок `Idempotency-Key` — уникальную строку длиной до 100 символов, обычно UUID. Повторный запрос с тем же ключом в течение 24 часов с тем же нормализованным телом (счета и числовое значение суммы) возвращает текущее состояние ранее созданного перевода с кодом 200 и не списывает деньги повторно. Ключ глобален для всех клиентов. Другое тело с действующим ключом даёт 409 `IDEMPOTENCY_CONFLICT`. Срок отсчитывается от `createdAt`: в момент истечения 24 часов или позже ключ можно использовать для новой операции; история старой сохраняется. Проверка действующего ключа предшествует проверке перегрузки.

## 7. Уведомления

Отправитель получает уведомление о финальном статусе перевода.

| Событие | Текст |
| --- | --- |
| `TransferCompleted` | Перевод {сумма} ₽ на счёт {номер счёта получателя} выполнен. Комиссия {комиссия} ₽. |
| `TransferFailed` | Перевод {сумма} ₽ на счёт {номер счёта получателя} не выполнен. Средства {сумма + комиссия} ₽ возвращены на счёт {номер счёта отправителя}. |

Суммы в тексте — с пробелом между разрядами и запятой перед копейками: `1 500,00`.

## 8. События

Обменник `transfers`, тип `topic`.

| Ключ маршрутизации | Событие | Очередь потребителя |
| --- | --- | --- |
| `transfer.created` | `TransferCreated` | `accounting.transfer-created` (учёт) |
| `transfer.completed` | `TransferCompleted` | `notifications.transfer-events` (уведомления) |
| `transfer.failed` | `TransferFailed` | `notifications.transfer-events` (уведомления) |

Тело события — JSON. Денежные поля — JSON number с двумя знаками после запятой, время — ISO 8601 со смещением.

`TransferCreated`:

```json
{
  "eventId": "0b8e4a8e-6a4b-4a51-9a52-2d7b0b3c1f10",
  "eventType": "TransferCreated",
  "transferId": "5f0c2a9e-3c1d-4f7e-b1a2-9d8e7f6a5b4c",
  "transferType": "OTHER",
  "fromAccount": "40817810000000000011",
  "toAccount": "40817810000000000021",
  "amount": 20000.00,
  "commission": 100.00,
  "totalDebited": 20100.00,
  "currency": "RUB",
  "occurredAt": "2027-03-15T12:00:00.000+03:00"
}
```

`TransferCompleted` и `TransferFailed` содержат `eventId`, `eventType`, `transferId`, `fromAccount`, `toAccount`, `amount`, `commission`, `currency`, `occurredAt`. `TransferFailed` дополнительно содержит `reason` и `refundedAmount` — возвращённую отправителю сумму.

Требования к обработке:

- Учёт зачисляет получателю ровно сумму перевода `amount`.
- Сообщения могут доставляться повторно. Повторная доставка события не должна приводить к повторному зачислению или повторному уведомлению.
- Сообщение, которое не удалось обработать три раза подряд, перекладывается в очередь `transfers.dlq` и не мешает обработке остальных.

## 9. Отчёт об обороте

`GET /api/v1/reports/turnover?date=ГГГГ-ММ-ДД` возвращает оборот за дату по МСК (по умолчанию — за сегодня): число переводов, сумму переводов и сумму комиссий. В отчёт попадают только переводы в статусе `COMPLETED`, завершённые в эту дату.

## 10. API

Базовый путь — `/api/v1`. Тела запросов и ответов — JSON.

| Метод | Путь | Что делает | Успешный ответ |
| --- | --- | --- | --- |
| `POST` | `/transfers` | Создать перевод | 202 — перевод создан; 200 — повтор по `Idempotency-Key` |
| `GET` | `/transfers/{transferId}` | Перевод | 200 |
| `GET` | `/accounts/{accountNumber}` | Счёт: владелец, остаток, статус | 200 |
| `GET` | `/accounts/{accountNumber}/operations` | Последние 100 проводок по счёту | 200 |
| `GET` | `/clients/{clientId}/limits` | Использованный дневной лимит и бесплатный порог | 200 |
| `GET` | `/clients/{clientId}/notifications` | Последние 100 уведомлений клиента | 200 |
| `GET` | `/reports/turnover` | Отчёт об обороте (раздел 9) | 200 |

### 10.1. Создание перевода

Заголовок `Idempotency-Key` обязателен.

| Поле | Тип | Обязательно | Ограничения |
| --- | --- | --- | --- |
| `fromAccount` | string | да | 20 цифр |
| `toAccount` | string | да | 20 цифр |
| `amount` | number | да | 10,00–300 000,00 включительно, не более двух знаков после запятой |

Ответ:

```json
{
  "transferId": "5f0c2a9e-3c1d-4f7e-b1a2-9d8e7f6a5b4c",
  "status": "PROCESSING",
  "transferType": "OTHER",
  "fromAccount": "40817810000000000011",
  "toAccount": "40817810000000000021",
  "amount": 20000.00,
  "commission": 100.00,
  "currency": "RUB",
  "createdAt": "2027-03-15T12:00:00.000+03:00",
  "completedAt": null
}
```

`completedAt` — время перехода в финальный статус (`COMPLETED` или `FAILED`). У неуспешного перевода есть поле `failReason`.

### 10.2. Ошибки

Тело ошибки: `{"code": "...", "message": "..."}`.

| HTTP | `code` | Когда |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Нет `Idempotency-Key`, неверный формат поля, сумма вне допустимого диапазона |
| 404 | `ACCOUNT_NOT_FOUND` / `CLIENT_NOT_FOUND` / `TRANSFER_NOT_FOUND` | Неизвестная сущность |
| 409 | `IDEMPOTENCY_CONFLICT` | Другой запрос с действующим ключом |
| 422 | `ACCOUNT_BLOCKED` | Списание с заблокированного счёта |
| 422 | `ACCOUNT_CLOSED` | Счёт отправителя или получателя закрыт |
| 422 | `DAILY_LIMIT_EXCEEDED` | Превышен дневной лимит |
| 422 | `INSUFFICIENT_FUNDS` | Недостаточно средств |
| 503 | `SERVICE_UNAVAILABLE` | Сервис перегружен (раздел 11). Ответ содержит заголовок `Retry-After` |

## 11. Нефункциональные требования

- Нагрузка — 50 новых `POST /api/v1/transfers` в секунду, стандартная история 30 000 переводов, 2000 пар клиентов, `OTHER` на 100,00 ₽, уникальный ключ на каждый запрос. Опрос статусов и метрик учитывается отдельно.
- При этой нагрузке не менее 95 % принятых (HTTP 202) переводов переходят в финальный статус не позднее 2 секунд после создания.
- Время ответа принятых `POST /transfers` — 95-й перцентиль не более 500 мс по полной выборке. Отказы и ошибки считаются отдельно. Миллион записей не требуется. Подтверждающий профиль: 180 с на 50 запросов/с, первые 30 с прогрев, следующие 150 с измерение. Когорта определяется началом POST в измерительном интервале; незавершённые после дренирования до 120 с остаются в знаменателе доли завершившихся за 2 с.
- Защита от перегрузки: если в очереди учёта больше 1 000 необработанных сообщений, новые переводы отклоняются с кодом 503 и заголовком `Retry-After: 1`. Перевод при этом не создаётся, деньги не списываются.

## 12. Данные и наблюдение

Денежные вычисления выполняются десятично, округление HALF_UP. Сумма в JSON передаётся числом: `100`, `100.0`, `100.00` равнозначны. Время — ISO 8601 со смещением; границы дня/месяца — полуинтервалы [начало, следующее начало) по МСК. `FAILED` освобождает дневное использование и месячный бесплатный порог.

БД H2 2.5.252 доступна только для SELECT через H2 JDBC и совместимый протокол PostgreSQL. Денежные столбцы DECIMAL(19,2), время TIMESTAMP WITH TIME ZONE. Основные столбцы:

| Таблица | Ключ и поля |
| --- | --- |
| `clients` | `client_id` PK, `full_name` |
| `accounts` | `account_number` PK, `client_id`, `currency`, `balance`, `status`, `opened_at` |
| `transfers` | `transfer_id` UUID PK, `idempotency_key`, `client_id` отправителя, `from_account`, `to_account`, `transfer_type`, `amount`, `commission`, `status`, `fail_reason`, `created_at`, `completed_at` |
| `postings` | `posting_id` PK, `transfer_id` (NULL для начального остатка), `account_number`, `direction` CREDIT/DEBIT, `posting_type` OPENING/AMOUNT/COMMISSION/REFUND, `amount`, `created_at` |
| `notifications` | `notification_id` PK, `client_id` отправителя, `transfer_id`, `text`, `created_at` |

При отказе до принятия нет перевода, проводок, списания и события. `GET /api/v1/health` возвращает `status=UP`, `time` и `clockShifted`. `/metrics` — текст Prometheus, накопительные счётчики за время процесса и текущая глубина очередей; сброс данных не обнуляет счётчики процесса. Поля `createdAt`/`completedAt` позволяют измерять задержку до финала без погрешности опроса.

Тестовый API подготовки и восстановления описан в README участника. Он не является предметом поиска дефектов. Все направления получают один контракт; найденные отклонения отражаются в отчёте и не заменяют построение тестирования.
