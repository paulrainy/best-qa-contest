# Исполненный эталон ручного тестирования

Материал жюри. Стратегия, дизайн, кейсы и объяснения — Markdown; доказательства — фактические HTTP/SQL-ответы и снимки консолей. Это самостоятельное ручное покрытие F01–F18, без готового автоматизированного тестового проекта.

Полный основной набор повторно исполнен после снятия намеренных дефектов: M01–M18 PASS. Текущий хеш, независимая проверка и ограничения — в [отчёте](report.md); старые доказательства помечены отдельно.

## Порядок повторения

1. Прочитать [условие и подключения](../../participant/README.md), [ТЗ](../../participant/spec.md), [стратегию](test-strategy.md) и [дизайн](test-design.md).
2. На выделенном стенде запустить готовый JAR ручной выдачи: Windows `stand/run.cmd`, macOS/Linux `bash stand/run.sh`. Нужна соответствующая платформе Java 17 или 21. Maven, Python и сеть для запуска не нужны. При получении через Git предварительно установить LFS, выполнить `git lfs install --local` и `git lfs pull`.
3. Зафиксировать версии/хеш и исходное состояние M01. До своей сессии один раз вызвать `POST /api/test/reset`; предупредить других пользователей стенда, так как это удаляет данные. Во время кейсов reset не используется.
4. Открыть HTTP-клиент (например, curl/curl.exe, Postman), Qpid-консоль и читающий SQL-клиент H2. Консоли и тестовый API описаны в README участника. Для H2 Shell достаточно драйвера из `stand/lib/`; пример ниже.
5. Готовить собственные данные по [test-data.md](test-data.md). Для каждого кейса записывать **свои** A/B/CA/T/ключи; номера из доказательств автора не являются входными данными повторения.
6. Выполнить [M01–M18](test-cases.md), включая таблицы вариантов. Сначала сравнить с ожидаемым по ТЗ, затем заполнить фактическое. Для одиночного перевода без намеренной паузы наблюдать финал до 10 секунд; отдельно записывать PROCESSING по истечении срока, FAILED и ошибку клиента.
7. После любого глобального изменения, включая остановку кейса, выполнить C01: resume обоих потребителей, вернуть часы, проверить состояние и завершение нового OWN 100. Для M14 дополнительно вернуть настройку локального HTTP-порта и удалить собственную очередь. Если исходные глобальные настройки отличались, восстановить именно сохранённые значения.
8. Провести [EX01/EX02](exploratory-sessions.md), выполнить и интерпретировать [SQL](sql-reconciliation.md), оформить [расхождения](findings.md), [отчёт](report.md) и [защиту](defense.md). Не использовать ответы автора как ожидаемые вместо требований.

Пример отдельного ручного запроса с новыми данными и уникальным ключом:

```bash
curl -i -X POST http://localhost:18400/api/test/accounts \
  -H 'Content-Type: application/json' \
  --data '{"balance":1000000.00,"status":"ACTIVE"}'
```

В PowerShell использовать `curl.exe` и подходящее для оболочки экранирование JSON. Подстановки последующих запросов описаны в test-data.md и кейсах; коллекция с автоматическими проверками не требуется.

Пример SQL-клиента из каталога `participant/stand/`:

```bash
java -cp lib/h2-2.5.252.jar org.h2.tools.Shell \
  -url jdbc:h2:tcp://localhost:19400/mem:stand -user qa -password qa \
  -sql 'SELECT COUNT(*) AS HISTORY FROM transfers;'
```

## Как читать результат автора

[Трассировка](traceability.md) связывает требование, F-группу, кейс и доказательство. В основной сессии все18 групп PASS, включая все указанные варианты. Дополнительная EX03 выявила несоответствие404 для неизвестного клиента уведомлений. Эти результаты относятся к данному объёму и сборке, а не являются квотой находок или доказательством полного отсутствия ошибок.

[Реестр текущей сессии](evidence/current-build/data-register.md) содержит реальные собственные идентификаторы. JSONL — журнал явных действий HTTP-клиента: время, метод, путь, тело запроса, ключ, статус/заголовки/сырой ответ. HTTP-вызовы фиксировались по одному, результаты интерпретировались исполнителем; Java/Python-эталоны не использовались для ручного прогона. Временный транспортный журналировщик автора не нужен для повторения и не входит в выдачу.

SQL TXT — вывод читающего клиента; синтетические VALUES-контроли помечены отдельно от настоящих данных. Срез M18 до завершения 400 и поздний SQL-срез имеют разные, объяснённые суммы. PNG подтверждают вход в обе консоли на Java 17/21. Неисполненные платформы и виды проверок перечислены в отчёте; локальный Mac не подтверждает Windows/ВДИ.
