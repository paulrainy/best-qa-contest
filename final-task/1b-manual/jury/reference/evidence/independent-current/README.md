## Решения при выполнении и границы приёмки

- Существующий participant/README использован без дублирования: запуск, подключения и задача уже описаны. Риск неполной инструкции проверен чтением по ролям и независимым повтором шести групп; отдельный новый стартовый проект не создавался.
- Для чтения своей копии события M14 разрешена временная настройка локального Qpid HTTP-порта с немедленным восстановлениемfalse и удалением своей очереди. Это описанные дополнительные ручные действия; вариант требует аккуратной очистки и не расширяет авторизацию за пределы локального учебного стенда.
- Другой порядок проверял изоляцию восьми обычных карточек на выбранных рискованных вариантах. Все первичные варианты выполнены полностью, но второй полный перебор параметров не заявляется; дополнительное покрытие такого перебора остаётся за пределами приёмки.
- Начальные остатки разрешено брать из ответов создания собственных счетов; после дополнительной подготовки требуется новое чтение. Это опирается на контракт корректного тестового API; отдельная проверка каждой его внутренней операции не выполнялась.
- Текущее расхождение MF01 оформлено по фактическим доказательствам без изменения общего JAR в ручном плане. Ни одна обязательная группа им не блокируется; цена решения — сохраняющееся несоответствие API и необходимость решения перед выдачей стенда.
- Независимый исполнитель повторяет согласованную выборку, а полный набор, исследовательские сессии, консоли17/21 и остальные SQL-контроли подтверждены авторскими доказательствами. Это достаточный объём данного плана, но слабее независимого повторения всех действий.
- Неисследованные Windows/ВДИ/AMD64, НФТ, гонки, redelivery/DLQ, внутренние причины старых дефектов и готовность других направлений не включены в вывод о ручном эталоне. Саму MF01 независимо заново не воспроизводили. Цена этих ограничений — отсутствие основания объявлять готовность продукта целиком; пилот и отдельные проверки остаются открытыми.

После интеграции выполнены `check_distribution.py --check` (четыре выдачи совпадают с манифестом), `git lfs fsck`, проверка относительных файловых ссылок и `git diff --check`. Новый адресный процесс M13 также остановлен после C01. Исходники/бинарники/контракт не менялись, автоматические Java/Python-эталоны и тесты других упражнений этим ручным этапом повторно не запускались.
