# Уточнение M13: время истечения от собственного createdAt

11.11.2026, автор эталона, macOS27.2/ARM64, Java21.0.13.0.3. Свежий процесс готовой ручной выдачи, тот же [SHA-256](stand-sha256.txt). Это адресная проверка замечания I01 независимого ревью, а не ещё один полный прогон или независимое исполнение M13. Начальный reset и подготовка — [SESSION](SESSION.jsonl), все действия — [M13](M13.jsonl).

Прежний шаг воспроизведён с задержкой оператора: после начальных часов15.01.2033 12:00 часы переведены на12:05 перед первым POST. Так моделируется задержка без ожидания пяти реальных минут. Первый перевод `601a0983-7e99-4b39-b94e-e0ded4bf1bcc` принят202, `createdAt=2033-01-15T12:05:00.077262+03:00`. После прежнего фиксированного PUT на16.01 12:00:01 повтор вернул200 и старый T:24 часа ещё не истекли. Поведение продукта корректно, ожидание202 в прежней инструкции в этой ситуации неверно.

После правки инструкции установлено время собственного `createdAt + 24 часа + 1 минута`, с миллисекундной точностью клиента: `2033-01-16T12:06:00.077+03:00`. GET часов подтвердил `12:06:00.152653+03:00`, позже истечения. Тот же ключ `manual-m13-ttl-recheck-20261111` и тело100 дали202 с новым T=`7b96c288-2262-4d26-ad86-90017fef8c76`, затем COMPLETED. Старый T сохранён, A=`40817810000000020061`/999800, B=`40817810000000020062`/200. [SQL](SQL.txt) подтвердил два разных завершённых перевода по ключу, ноль расхождений остатков с проводками и ноль PROCESSING в области четырёх собственных счетов20061–20064.

Запросы SQL выполнены читающим H2 Shell:

```sql
SELECT transfer_id,status,created_at FROM transfers
WHERE idempotency_key='manual-m13-ttl-recheck-20261111' ORDER BY created_at;
SELECT a.account_number,a.balance,
       COALESCE(SUM(CASE WHEN p.direction='CREDIT' THEN p.amount ELSE -p.amount END),0) AS BY_POSTINGS
FROM accounts a LEFT JOIN postings p ON p.account_number=a.account_number
WHERE a.account_number BETWEEN '40817810000000020061' AND '40817810000000020064'
GROUP BY a.account_number,a.balance
HAVING a.balance<>COALESCE(SUM(CASE WHEN p.direction='CREDIT' THEN p.amount ELSE -p.amount END),0);
SELECT transfer_id,status FROM transfers
WHERE from_account BETWEEN '40817810000000020061' AND '40817810000000020064'
  AND status='PROCESSING';
```
