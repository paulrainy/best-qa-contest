Один и тот же JAR проверен при запуске на Java 17.0.21 и 21.0.13.0.3; основная сессия и SQL — Java 21. [Версии](java21-version.txt), [Java17](java17-version.txt), [ОС](os.txt), [SHA-256](stand-sha256.txt).

SHA-256 стенда: `73c7773c0c029702e781f3dfd3e625046e5e69866dd1def82f71c47511113ecf`. Исходники стенда не использовались для исполнения, JAR не менялся. HTTP-клиент, консоли, SQL и ручная интерпретация результатов заменяют предположения фактическими доказательствами; автоматические Java/Python-эталоны не запускались вместо ручной работы.

## Покрытие и факты

Основной набор M01–M18 исполнен: 16 групп PASS, M10 и M16 FAIL относительно требований. Выполнены все варианты основной части: 5 по сумме/точности, 12 негативных по структуре/сущности/средствам, 18 по статусам OWN/OTHER, 3 по лимиту, минимум/округление/месяц, повтор/конфликт/истечение, событие/учёт/возврат/уведомления/оборот. [Трассировка](../traceability.md), [кейсы с фактами](../test-cases.md).

- M10: комиссия 200 вместо 100 и лишнее списание 100. В другом порядке на новых данных наблюдение повторилось.
- M16: перед второй операцией 900000; после FAILED осталось 899600, REFUND40000 вместо40400. Подготовка 100000+40000 с комиссией400 изолирована от M10.
- M18: до завершения400 оборот D+1=1/200/0, затем2/600/0. SQL и API совпали в каждом отдельном срезе; значения не смешивались.
- Все C01 после глобальных сценариев завершены: оба потребителя RUNNING, реальные часы, health UP и новый контрольный OWN100 с верными остатками. Собственная очередь M14 удалена, параметр локального HTTP-порта восстановлен false.

## Исследование, SQL и повтор

[EX01](../exploratory-sessions.md) показал независимость финала учёта от готовности уведомления, осмысленное прекращение наблюдения при намеренной паузе и восстановление. [EX02](../exploratory-sessions.md) проверил повтор после изменения статуса счёта: старый ключ возвращает прежнюю операцию, новый запрос проверяет актуальное состояние.

[SQL](../sql-reconciliation.md) исполнен по собственным данным. Основной срез:81 свой счёт,49 переводов (46 COMPLETED/3 FAILED). Сверки остатков, отрицательных остатков, одного зачисления, дебетов и незавершённых после очистки — без строк нарушений. Возврат FAILED дал одну строку недостачи400. Пустые ответы проверены на чувствительность через явные VALUES/CTE-контроли; это не подмена реальных результатов и не записи в БД.

Для проверки независимости между карточками выполнен повтор на новых данных без reset: M12→M10→M07→M06→M05→M04→M03→M02. В параметризованных M04/M05/M06 повторены выбранные рискованные варианты: верхняя граница/точность, три класса отказов, заблокированное списание OWN/разрешённое зачисление. Это проверка другого порядка карточек, не заявление о втором полном прогоне всех вариантов. Результаты совпали, глобальные настройки остались исходными. [Повтор](R-M12.jsonl), [SQL](SQL-reorder.txt), [финальное состояние](R-final.jsonl).

Независимый исполнитель повторяет F02/F06/F10/F12/F15/F16 и SQL по одному README. Результат этой заключительной проверки фиксируется после исполнения, до окончательной приёмки.

## Решение и ограничения

Текущая сборка требует исправления денежных правил перед выпуском: неверная комиссия и неполный возврат затрагивают деньги клиента. После исправлений повторить денежные, асинхронные и SQL-проверки с прежними корректными ожиданиями. Решение основано на наблюдениях, а не заранее заданном обязательном ответе участника.

Не выполнены Windows/ВДИ, нагрузка и НФТ, гонки, redelivery/ядовитые сообщения, долговременная надёжность, сбои инфраструктуры и промышленная безопасность. Пилот целевой Windows/ВДИ до официальной выдачи остаётся открытым. Намеренные паузы и сдвиг часов в кейсах не являются измерениями производительности. Административный UI брокера не проходил полный функциональный аудит; наблюдение события воспроизводится документированными REST-действиями.

## Наблюдаемые признаки для будущей шкалы

Баллы и веса здесь не назначаются; сравнивать направления предстоит после всех четырёх эталонов.

| Признак | Доказательство полноценного выполнения | Пример частичного выполнения |
| --- | --- | --- |
| Дизайн по рискам | Правило связано с границей/классом/решением и кейсом | Только успешные сценарии |
| Воспроизводимые данные | Свои клиенты/счета, конкретные исходные суммы и подготовка | Зависимость от запомненного чужого счёта |
| Достоверное исполнение | Запрос, ответ, фактическое, время и собственные ID | Заполненное по предположению фактическое |
| Асинхронность | Различены PROCESSING/FAILED/timeout, сверены деньги и уведомления | Проверен только POST202 |
| SQL | Исполнение, область, строки/пустой результат, контроль чувствительности | Только текст запроса |
| Очистка | Возврат состояния и следующий контроль после остановки | Потребитель остался на паузе |
| Выводы | Риски и решение связаны с доказательствами и ограничениями | Необоснованный вывод о готовности |
