# Задание: код-ревью автотестов

## Что нужно сделать

Коллега написал автотесты на операции с картой и прислал их на ревью. Проведите ревью так, как сделали бы это в merge request.

Задание из двух частей:

- **Основная часть, обязательная** — десять тестов на Java + Selenide в стиле проекта `efr_v2`.
- **Дополнительная часть, по желанию** — пять тестов на Java + Playwright. Баллы за неё начисляются сверх основной части, пропуск не штрафуется.

## Основная часть: Selenide

Материалы:

- `code/CardsHelper.java` — общий хелпер;
- `code/TK900101Test.java` … `code/TK900110Test.java` — автотесты;
- тест-кейсы из Test IT, которые эти автотесты автоматизируют, — ниже.

Классы страниц (`CardProfilePage`, `NewEfrClientSearchPage` и другие) и `BaseTest` не приложены — считайте, что они работают корректно.

## Дополнительная часть: Playwright

Материалы:

- `code-playwright/BaseTest.java` — базовый класс: запуск браузера, контекст и страница для теста, вход в ЕФР;
- `code-playwright/CardPage.java` — page object карточки карты;
- `code-playwright/TK900111Test.java` … `code-playwright/TK900115Test.java` — автотесты;
- тест-кейсы — в конце файла.

Тесты на JUnit 5 и Playwright for Java, отчёт — Allure (`allure-junit5`). Классы `Config`, `CardsApi`, `Client`, `CardInfo` и `User` не приложены — считайте, что они работают корректно: `Config` читает стенд, токен API и учётные записи ролей из переменных окружения, `CardsApi` готовит данные через API.

## Формат ответа

Таблица, одно замечание — одна строка. Для дополнительной части — отдельная таблица в том же формате.

| № | Файл:строка | Что не так | Почему это проблема | Как исправить |
| --- | --- | --- | --- | --- |
| 1 | `TK900101Test.java:12` | … | … | … |

Если одна и та же проблема встречается в нескольких местах, достаточно одного замечания со всеми строками.

Пишите только замечания по существу. За замечание к корректному коду баллы снимаются.
