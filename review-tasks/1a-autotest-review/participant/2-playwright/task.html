Код-ревью автотестов на Playwright

📋 Что нужно сделать

Коллега написал автотесты и просит вас проверить их, прежде чем они попадут в общий проект.

  1. Откройте папку src/test/java/ru/rshb/pw/cards/. Там лежат 5 тестов TK900111Test.java … TK900115Test.java, базовый класс BaseTest.java (запускает браузер и входит в приложение) и CardPage.java (описание страницы карты).
  2. Каждый тест написан по тест-кейсу. Они располагаются в конце этого файла.
  3. Найдите в тестах всё, что сделано неправильно или плохо.
  4. Запишите каждую проблему отдельной строкой в таблицу. Таблица для ответов уже подготовлена (answer-template.xlsx).

Тесты написаны на JUnit 5 и Playwright for Java, отчёт — Allure (allure-jupiter).

Папку src/main/ проверять не нужно. Там песочница — маленькое приложение, на котором запускаются тесты, и классы Config, CardsApi, Client, CardInfo и User. Считайте, что в них всё правильно.

Тесты можно запустить — как это сделать, написано в разделе «Как запустить тесты».

📝 Формат ответа

Заполните таблицу answer-template.xlsx. В ней по 5 строк на каждый тест, строки можно добавлять.

ТестФайл:строкаЗамечание
TK900111TK900111Test.java:12…

В колонке «Замечание» напишите, что не так и почему это проблема. Исправление предлагать не обязательно, но верное исправление тоже показывает, что вы поняли причину.

Обязательно указывайте файл и строку. Замечание без места не засчитывается: «везде sleep» — не замечание.

Если проблема одного теста ломает другой тест, достаточно написать её у одного из них.

🎯 Как считаются баллы

  • Задание — это 20 тестов: 10 на Selenide, 5 на Playwright и 5 на SQL. Все равноправны. Песочницы пронумерованы: 1-selenide, 2-playwright, 3-sql, в таком же порядке тесты идут в answer-template.xlsx.
  • В каждом тесте ровно 5 дефектов. За каждый найденный дефект с верной причиной — 1 балл, максимум 100.
  • В тестах и общем коде есть ловушки — места, которые выглядят подозрительно, но написаны правильно. За каждое замечание, которое называет ошибкой правильный код, снимается 2 балла.

🚀 Как запустить тесты

Что нужно установить

  • Java 17 или новее. Проверить: java -version.
  • Maven 3.6.3 или новее. Проверить: mvn -v.
  • Яндекс Браузер или Google Chrome. Если установлен Яндекс Браузер, тесты идут в нём, иначе в Chrome. Отдельно скачивать браузер или драйвер не нужно.

Стенд не нужен. Тесты работают с песочницей, она запускается сама вместе с тестами.

При первом запуске Maven скачает библиотеки, около 270 МБ: в библиотеке Playwright лежит Node.js для всех систем. Всё скачанное остаётся в этой папке, в .m2.

Запуск из терминала

  1. Откройте терминал в этой папке — там, где лежит pom.xml.

  2. Запустите все тесты:

    mvn test
  3. В конце Maven напишет, сколько тестов прошло и сколько упало.

Другие варианты запуска:

Что нужноКоманда

В PowerShell параметры с точкой или решёткой берите в кавычки:

mvn test "-Dtest=TK900111Test#blockCompromisedCard"

Пока тесты идут с окном браузера, не печатайте на клавиатуре: нажатия могут попасть в поле, которое заполняет тест.

В Git Bash на Windows русский текст в консоли выводится кракозябрами. Один раз выполните в Git Bash:

echo 'export MAVEN_OPTS="$MAVEN_OPTS -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8 -Dsun.stdout.encoding=UTF-8 -Dsun.stderr.encoding=UTF-8"' >> ~/.mavenrc

Maven читает этот файл при каждом запуске из Git Bash, больше ничего делать не нужно. В PowerShell, cmd и IntelliJ IDEA настройка не нужна и не действует.

Запуск из IntelliJ IDEA

  1. File → Open → выберите эту папку. IDEA сама поймёт, что это Maven-проект.
  2. Чтобы IDEA тоже качала библиотеки в папку проекта, откройте Settings → Build, Execution, Deployment → Build Tools → Maven. В поле Local repository поставьте галочку Override и укажите папку .m2/repository внутри этой папки. Потом нажмите справа на панели Maven кнопку обновления (Reload All Maven Projects).
  3. Откройте любой тест, например TK900111Test, и нажмите зелёную стрелку рядом с именем класса.
  4. Все тесты сразу: правой кнопкой по папке src/test/java → Run 'All Tests'.

Где смотреть результат

  • Вывод в консоли — какие тесты прошли и с какой ошибкой упали остальные.
  • Отчёт Allure (mvn allure:serve) — шаги каждого теста.
  • Трейс Playwright — в папке build/traces, по файлу на тест. Чтобы открыть, перетащите файл на страницу https://trace.playwright.dev. Файл никуда не отправляется, страница читает его в браузере. В трейсе видно каждое действие теста, снимок страницы и сетевые запросы.

То, что тест зелёный, ещё не значит, что к нему нет замечаний.

Посмотреть песочницу своими руками

Можно открыть песочницу в браузере и пройти кейс вручную:

mvn exec:java

Откройте http://localhost:18080/efr/. Остановить — Ctrl+C в терминале.

РольЛогинПароль
Клиентский менеджерrf_card_mng1Mng1#Playground
Менеджер-операционист (видит вкладку «Реквизиты»)rf_m_oper4Oper4#Playground

Клиент, который есть всегда, — паспорт 4510 123456. Остальных клиентов тесты создают сами.

Что полезно знать про песочницу:

  • данные хранятся только пока она запущена — после перезапуска всё как в начале;
  • она отвечает с задержками, как настоящий стенд: блокировка — около 2 секунд, временная блокировка, её снятие и закрытие карты — около 1 секунды;
  • токен API, который выдаёт песочница, живёт 15 минут;
  • если она уже запущена через mvn exec:java, тесты будут работать с ней и свою не поднимут.

Можно ли что-то менять

Да. Запускайте тесты в любом порядке, правьте их, правьте песочницу в src/main/ — например, чтобы проверить, заметит ли тест ошибку в приложении. Сдавать изменённый код не нужно: оценивается только таблица замечаний.
