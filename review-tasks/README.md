# Задания на ревью чужих артефактов

Черновик. Синтетические задания для участников, у которых сейчас нет своих автотестов или тест-кейсов, пригодных для оценки по чек-листу (см. `rating-tasks.md`).

## Идея

Мы сами пишем артефакт и закладываем в него дефекты. Отсюда:

- **ключ известен заранее** — проверка сводится к сверке с ним, экспертиза нужна только при подготовке;
- **дефекты привязаны к пунктам наших чек-листов** — задание проверяет то же, что и оценка собственных артефактов;
- **шкала та же, 0–5** — баллы сравнимы с участниками, сдавшими свои артефакты.

## Варианты

### 1а. Код-ревью автотестов — для автоматизаторов

**Статус:** материал готов, см. `1a-autotest-review/`.

- **Даём:** семь тестов в стиле `efr_v2`, общий хелпер и связанные кейсы Test IT.
- **Заложено:** 18 дефектов по пунктам чек-листа автотестов и 8 ловушек — корректный код, похожий на ошибку. Один тест почти чистый.
- **Сдаёт:** таблицу замечаний «файл:строка — что не так — почему — как исправить».
- **Проверка:** +1 за найденный дефект с верной причиной, −1 за ловушку, итог приводится к шкале 0–5.

Файлы:

- `1a-autotest-review/participant/` — всё, что отдаём участнику: `task.md` (задание и кейсы Test IT) и `code/`. Папку отправляем целиком, архивом;
- `1a-autotest-review/jury/answer-key.md` — ключ, только жюри.

### 1б. Аудит тест-кейсов — для ручных тестировщиков

**Статус:** не начато.

- **Даём:** 10 кейсов на одну фичу (например, перевод между счетами): 3 хороших, 7 с 1–2 дефектами по пунктам чек-листа ручных кейсов, в одном нарушен стоп-пункт.
- **Сдаёт:**
  1. таблицу «кейс × 5 пунктов чек-листа» с оценками 0/1;
  2. два худших кейса, переписанных по-своему.
- **Проверка:**
  - часть 1 — совпадение с ключом по ячейкам (можно формулой в Excel), пересчёт в 0–3;
  - часть 2 — оба кейса по тому же чек-листу, 0–2.
- **Плюс:** участник применяет наш чек-лист и показывает, что понимает, какой кейс хороший.

### 1в. Аудит баг-репортов — для всех

**Статус:** не начато.

- **Даём:** 5 баг-репортов с дефектами: нет шагов; нет разделения на ожидаемый и фактический результат; нет версии и стенда; заголовок «не работает»; неверная серьёзность; два бага в одном; нет лога или скриншота.
- **Сдаёт:** замечания по каждому репорту и один репорт, переписанный целиком.
- **Проверка:** сверка замечаний с ключом, переписанный репорт — по короткому чек-листу.
- **Где использовать:** кандидат в **общие задания**, заодно заменяет отклонённую метрику «количество дефектов в Jira».

## Как устроены папки заданий

В каждом задании две папки:

- `participant/` — самодостаточный комплект для участника, ссылки в `task.md` — относительные внутри этой папки. Ничего жюрийного сюда не кладём.
- `jury/` — ключ и заметки для проверки.

Архив для отправки собирается из папки задания так, чтобы в него не попали служебные файлы macOS:

```bash
cd review-tasks/1a-autotest-review/participant && zip -r ../autotest-review.zip . -x '.DS_Store'
```

## Риски

- **Утечка ключа.** Задания выполняют два месяца, рейтинг публикуется еженедельно — ответы могут разойтись между участниками. Варианты защиты:
  - два варианта материала;
  - единый срок сдачи для всех, а не по мере готовности.
- **Нейросети.** Решено не запрещать: участники работают как хотят. Большую часть заложенных дефектов нейросеть находит сразу, поэтому различают участников в основном ловушки — нейросеть склонна помечать подозрительный, но корректный код, а за такие замечания снимается балл.
- **Качество ключа.** Если в материале окажется незапланированный дефект или спорный пункт, баллы станут нечестными. Перед запуском материал решают 1–2 коллеги, не участвующие в конкурсе.

## Рекомендация

- **1а** — замена оценки артефактов для автоматизаторов.
- **1б** — то же для ручных тестировщиков.
- **1в** — в общие задания для всех.
