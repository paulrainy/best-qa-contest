# Задания на ревью чужих артефактов

Черновик. Синтетические задания для участников, у которых сейчас нет своих автотестов или тест-кейсов, пригодных для оценки по чек-листу (см. `rating-tasks.md`).

## Идея

Мы сами пишем артефакт и закладываем в него дефекты. Отсюда:

- **ключ известен заранее** — проверка сводится к сверке с ним, экспертиза нужна только при подготовке;
- **дефекты привязаны к пунктам наших чек-листов** — задание проверяет то же, что и оценка собственных артефактов;
- **шкала та же, 0–5** — баллы сравнимы с участниками, сдавшими свои артефакты.

## Варианты

### 1а. Код-ревью автотестов — для автоматизаторов

**Статус:** Selenide, Java + SQL и Playwright готовы, см. `1a-autotest-review/`.

- **Даём:**
  - основная часть:
    - десять тестов на Selenide в стиле `efr_v2`, общий хелпер и связанные кейсы Test IT. Тесты лежат в Maven-проекте с заглушкой ЕФР, их можно запустить локально;
    - пять тестов на Java + SQL в стиле `at_cft_2` (ЦФТ, РКО ФЛ): классы Criteria, которые собирают SQL для поиска данных, шаги с прямыми запросами к БД и упрощённая схема таблиц. Только чтение;
  - дополнительная часть по желанию — пять тестов на Playwright for Java (JUnit 5) с базовым классом и page object.
- **Заложено:**
  - в Selenide — 23 дефекта по пунктам чек-листа автотестов и 10 ловушек, то есть корректного кода, похожего на ошибку. Два теста почти чистые;
  - в Java + SQL — 10 дефектов и 5 ловушек. Половина дефектов — в самом SQL: `NOT IN` с `NULL`, `OR` без скобок, условие LEFT JOIN в `WHERE`, «последняя запись» без `ORDER BY`, синтаксис только для Oracle. Остальные — по пунктам чек-листа: зашитые ID справочника, `UPDATE` данных стенда, неполные проверки;
  - в дополнительной — 7 дефектов и 4 ловушки на знание Playwright: автоожидания, изоляция контекстов, web-first assertions. Один тест чистый.
- **Сдаёт:** таблицу замечаний «файл:строка — что не так — почему — как исправить» по каждой части отдельно.
- **Проверка:** +1 за найденный дефект с верной причиной, −1 за ловушку. Основная часть (Selenide и Java + SQL вместе) приводится к шкале 0–5, дополнительная даёт до +1 балла, итог — не больше 5.

Файлы:

- `1a-autotest-review/participant/` — всё, что отдаём участнику: `selenide/` (песочница с тестами на Selenide) и `sql/` (песочница с тестами на Java + SQL) — основная часть, `playwright/` (песочница с тестами на Playwright) — дополнительная. В каждой папке свой `task.md` с заданием и кейсами Test IT. Папку отправляем целиком, архивом;
- `1a-autotest-review/jury/answer-key.md` — ключ, только жюри.

### 1б. Аудит тест-кейсов — для ручных тестировщиков

**Статус:** не начато.

- **Даём:** 10 кейсов на одну фичу (например, перевод между счетами): 3 хороших, 7 с 1–2 дефектами по пунктам чек-листа ручных кейсов, в одном нарушен стоп-пункт.
- **Сдаёт:**
  1. таблицу «кейс × 5 пунктов чек-листа» с оценками 0/1;
  2. два худших кейса, переписанных по-своему.
- **Проверка:**
  - часть 1 — совпадение с ключом по ячейкам (можно формулой в Excel), пересчёт в 0–3;
  - часть 2 — оба кейса по тому же чек-листу, 0–2.
- **Плюс:** участник применяет наш чек-лист и показывает, что понимает, какой кейс хороший.

### 1в. Аудит баг-репортов — для всех

**Статус:** не начато.

- **Даём:** 5 баг-репортов с дефектами: нет шагов; нет разделения на ожидаемый и фактический результат; нет версии и стенда; заголовок «не работает»; неверная серьёзность; два бага в одном; нет лога или скриншота.
- **Сдаёт:** замечания по каждому репорту и один репорт, переписанный целиком.
- **Проверка:** сверка замечаний с ключом, переписанный репорт — по короткому чек-листу.
- **Где использовать:** кандидат в **общие задания**, заодно заменяет отклонённую метрику «количество дефектов в Jira».

### 1г. Ревью отчёта и скрипта НТ — для нагрузочников

**Статус:** материал готов, см. `1g-load-review/`.

- **Даём:** отчёт о НТ сервиса `cards-api` с шестью графиками из Grafana и план JMeter 5.6.3 с тестовыми данными.
- **Заложено:** 17 дефектов по пунктам черновика чек-листа отчёта НТ — 8 в скрипте, 9 в методике и выводах отчёта — и 8 ловушек. Главное, что проверяется: умеет ли участник по графикам найти настоящее узкое место и увидеть, что нагрузка на самом деле не подана.
- **Сдаёт:** таблицу замечаний «где — что не так — почему — как исправить».
- **Проверка:** +1 за найденный дефект с верной причиной, −1 за ловушку, итог приводится к шкале 0–5.

Файлы:

- `1g-load-review/participant/` — всё, что отдаём участнику: `task.md`, `report.md` с графиками в `img/` и `script/`;
- `1g-load-review/jury/answer-key.md` — ключ, только жюри;
- `1g-load-review/jury/charts.py` — генератор графиков отчёта. Нужен, только если меняются числа в отчёте.

### 1д. Код-ревью автотестов на Python — для автоматизаторов

**Статус:** не начато, ждём примеры кода от коллег.

То же задание, что 1а, для тех, кто пишет автотесты на Python:

- обязательно — 10 тестов на Python + pytest и инструмент, который будет в примерах, и 5 тестов на Python + SQL;
- по желанию — 5 тестов на Python + Playwright.

## Как устроены папки заданий

В каждом задании две папки:

- `participant/` — самодостаточный комплект для участника, ссылки в `task.md` — относительные внутри этой папки. Ничего жюрийного сюда не кладём.
- `jury/` — ключ и заметки для проверки.

Архив для отправки собирается из папки задания так, чтобы в него не попали служебные файлы macOS и результаты сборки:

```bash
cd review-tasks/1a-autotest-review/participant && zip -r ../autotest-review.zip . -x '*.DS_Store' '*/target/*' '*/.idea/*' '*/.m2/*' '*/.selenium/*' '*/.allure/*'
```

## Риски

- **Утечка ключа.** Задания выполняют два месяца, рейтинг публикуется еженедельно — ответы могут разойтись между участниками. Варианты защиты:
  - два варианта материала;
  - единый срок сдачи для всех, а не по мере готовности.
- **Нейросети.** Решено не запрещать: участники работают как хотят. Большую часть заложенных дефектов нейросеть находит сразу, поэтому различают участников в основном ловушки — нейросеть склонна помечать подозрительный, но корректный код, а за такие замечания снимается балл.
- **Качество ключа.** Если в материале окажется незапланированный дефект или спорный пункт, баллы станут нечестными. Перед запуском материал решают 1–2 коллеги, не участвующие в конкурсе.
