## 5. Что не так

### В материале

1. **Д05.3: пример ответа не сходится с regex.** В комментарии запроса `GET /api/v1/tasks` пример записан с пробелом после двоеточия: `"id": "TS-…"`. Regex в сценарии — `"id":"(.+?)"`, без пробела. На этом примере он не найдёт ничего, а ключ утверждает, что он ловит и ID задачи, и ID клиента. Замечание «regex вообще не сработает» по колонке «Засчитываем, если…» не засчитается. На компактном JSON дефект воспроизводится как в ключе (прогон 05). Исправленный сценарий 04 тоже рассчитан на компактный JSON: `"depositId":"(.+?)"`.
2. **Д08.4: скрипт «Время запроса» падает с ошибкой, а не кэшируется.** Ключ описывает механизм так: скрипт закэшируется с временем первого вызова. В прогоне JSR223 PreProcessor выдавал ошибку на каждом запросе, переменная `requestTime` не заполнялась. Итог для участника тот же (время одинаковое), но причина другая. Текст ошибки не сохранён; предположение — после подстановки `${__time(…)}` в тексте остаются кавычки или обратные косые, и Groovy не компилирует строку. **Нужно перепроверить отдельным запуском.**
3. **Д04.1, проверить формулировку.** В CSV-результатах и при включённом «Generate parent sample» (сценарий 01), и при выключенном (сценарий 04) есть строки и транзакции, и запросов. Ключ говорит «в результатах и запросы, и транзакция, итоговые цифры считаются дважды». Для слушателей это верно, для файла `.jtl` — возможно, нет. Глубоко не разбирал.

### В инструментах и упаковке

4. **`build_sheets.py ../1c-load-review` падает на Windows.** Сообщение: «протокол 11–15 старше исходника». Причина: `build_protocols.source_hash` считает хеш по байтам `.md`, а при `core.autocrlf=true` исходники выгружаются с CRLF. Хеш в `.docx` посчитан на Mac по LF.
5. **`build_jmx.py --check` на Windows не запустится.** Разделитель classpath зашит как `:`, путь к Java по умолчанию — Homebrew. Проверку пришлось запускать напрямую через `check_jmx.groovy`.
6. **`open-jmeter.bat` и `open-jmeter.command` не ловят LFS-указатели.** Проверяется только существование `ApacheJMeter.jar`. Если архив участника собрать из клона без `git lfs pull`, проверка пройдёт, а JMeter не стартует.
7. **Исправленные сценарии не запускаются из своей папки.** В `jury/fixed/scripts/data/` только `controllers.csv` и `new_clients.csv`, остальных файлов данных нет. Для чтения это не мешает, для прогона данные пришлось собирать вручную.
8. **`CLAUDE.md` и `AGENTS.md` не упоминают** папку `tools/`, Git LFS и запуск через `open-jmeter.*`.

Тесты генераторов (`pytest` в `review-tasks/tools`) на свободной машине: 98 прошли, 2 пропущены (им нужен `JMETER_HOME`). Проблему из пункта 4 тесты не ловят. Во время параллельных прогонов 5 тестов падали с `MemoryError` — это была занятая память, не код.
