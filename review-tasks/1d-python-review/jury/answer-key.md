# Ключ: код-ревью автотестов на Python (задание 1д)

**Только для жюри, участникам не отправлять.**

Задание — 20 тестов в одном проекте `participant/python/`: 10 на API и БД (TK900301–TK900310), 5 на Kafka (TK900311–TK900315), 5 на Playwright (TK900316–TK900320). Все тесты равноправны, части названы только для навигации. В каждом тесте ровно 5 дефектов, все в файле самого теста — всего 100. Ловушек 10, они лежат и в тестах, и в общем коде.

Общий код (`tests/conftest.py`, `tests/kafka/conftest.py`, `tests/ui/conftest.py`, `invest/`) дефектов не содержит. Каркас `framework/`, песочница `sandbox/` и корневой `conftest.py` участник не проверяет.

Стиль кода взят из бэкенд-тестов команды СИ (`previous-year/si-autotests/`): pytest, PyHamcrest с сообщениями, шаги `reporting.step`, `retrying`, отдельный класс с SQL-запросами к БД сервиса. Домен свой, чтобы авторы не узнали код.

Исправленные версии тестов — в `jury/fixed/python/tests/`, участникам не отправляются.

## Как считаем

- +1 за каждый дефект из ключа, найденный с верной причиной. Пункт чек-листа называть не обязательно, важно понять, что именно не так.
- Тест обязательно назван: замечание засчитывается только за тест, который в нём указан. «Везде sleep» без тестов не засчитывается.
- Если дефект в одном тесте ломает другой тест, замечание засчитываем у любого из двух — в колонке «Засчитываем, если…» это сказано. Считается такой дефект один раз.
- −2 за каждую ловушку, в которую попал участник. Попадание — участник считает место ошибкой и предлагает его исправить. Если он отметил место как подозрительное и сам объяснил, почему оно корректно, штрафа нет. Каждая ловушка штрафуется один раз, сколько бы раз её ни упомянули. Штраф снимается с общей суммы.
- Итог: `max(0, дефекты − 2 × ловушки)`, от 0 до 100.
- Замечания, которых нет в ключе, баллов не дают и не штрафуются. Спорные разбираем с Мариной Каприз.

Лист подсчёта — `jury/scoring-sheet.xlsx`: 100 строк дефектов и 10 строк ловушек, в каждой ставим 0 или 1, итог считает формула. Как проверять: для каждого замечания участника открыть в ключе все 5 строк названного теста и найти ту, с которой замечание совпадает по смыслу — сверять с колонкой «Засчитываем, если…». Номер строки нужен только чтобы быстрее найти нужную строку ключа: если участник указал строку неточно, но по смыслу замечание совпадает, засчитываем. Если участник описал симптом при запуске (падение на другой строке, `SKIPPED` или `XPASS` в выводе, строки в логе и т. п.), засчитываем там, где в колонке «Засчитываем, если…» это прямо сказано. Код открывать не нужно.

Дефекты, которые проявляются в других тестах:

- **Д301.5** — очистка в TK900301 удаляет чужих клиентов. При `pytest -n 4` от неё может упасть, дать ошибку или пропуститься любой тест, который в этот момент идёт на соседнем воркере. Замечание у такого теста с причиной «клиента удалила очистка в TK900301» — это Д301.5.
- **Д305.2** — TK900305 переключает общие данные по умолчанию на «Трейдер». Симптомы — у TK900309, TK900311 и TK900320. Если замечание у этих тестов не совпало ни с одной из их пяти строк, сверьте его с Д305.2.

Шаблон ответа участника — `participant/answer-template.xlsx`. Оба файла собираются из этого ключа скриптом `review-tasks/tools/build_sheets.py`: после правки ключа запустить его заново.

## Пункты чек-листа и технические категории

Каждый дефект относится к пункту чек-листа автотестов из `rating-tasks.md` или к технической категории. Пять дефектов теста не обязаны покрывать все пункты.

| Пункт | Что проверяем |
| --- | --- |
| 1 ⛔ | Ожидаемые результаты кейса покрыты проверкой |
| 2 | Нет жёстких пауз: ждём по условию, а не фиксированное время |
| 3 | Нет зашитых стендов, адресов, учёток и паролей |
| 4 | Тест не зависит от других тестов и от порядка запуска |
| 5 | При падении понятно, что сломалось |
| SQL | Запрос выбирает те данные, которые нужны тесту, и работает на любом стенде |
| Kafka | Сообщение своё, с нужным ключом, и тест дожидается его обработки |
| Playwright | Локаторы, автоожидание и действия Playwright используются как задумано |
| pytest | Пометки, фикстуры и проверки pytest работают так, как думал автор |

## Что видно в песочнице

Тесты участник может запустить в `participant/python/` (инструкция — в `participant/python/task.md`, раздел «Как запустить тесты»). Песочница — сервис на стандартной библиотеке Python, БД — SQLite-файл `build/invest.db`, Kafka — топики в памяти за HTTP-шлюзом QA Service на том же порту 18300. Сервис читает входящие топики раз в полсекунду.

Заглушки работают правильно, поэтому большинство дефектных тестов зелёные. Ниже — что видно при запуске. Остальные дефекты видны только в коде: это и есть суть задания — зелёный тест ещё не значит, что он что-то проверяет.

Прогоны на macOS, Python 3.10 из `.venv` песочницы, браузер — установленный Chrome, headless. Весь проект `pytest` — четыре раза, `pytest -n 4` — 15 раз (из них 10 — с `-v`, чтобы видеть воркеры). Части по отдельности — по три раза.

## Что проверить перед запуском

- После любой правки тестов пересобрать ключ: номера строк в нём точные. Из корня репозитория: `cd review-tasks/tools && .venv/bin/python build_sheets.py ../1d-python-review --show` печатает строки кода, на которые ссылается ключ, — у каждого дефекта в строке должна быть заложенная ошибка, у каждой ловушки — корректный код. Затем `cd review-tasks/tools && .venv/bin/python build_sheets.py ../1d-python-review` пересобирает шаблон ответа и лист подсчёта.
- Архив для участников собирать из `participant/` (с `answer-template.xlsx`) без `__pycache__`, `build/` и `.venv`. Они в `.gitignore`, поэтому подойдёт, например, `git archive`. Если в архив попадёт `__pycache__`, pytest возьмёт переписанный модуль из кеша и предупреждения Д301.4 участник не увидит.
- Прогнать на ВДИ (Яндекс Браузер) `pytest` и `pytest -n 4` и сверить результат с разделом «Что видно в песочнице». При `-n 4` на медленной машине от Д301.5 могут пострадать другие тесты, а TK900320 то проходит, то пропускается — так и задумано.

- Дать решить задание одному-двум коллегам, не участвующим в конкурсе. Если они находят меньше трети дефектов или спотыкаются о формулировку, упростить.
