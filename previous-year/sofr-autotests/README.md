# Автотест СОФР: выжимка

Выжимка по папке «…_пример_СОФР» из `help-docs`. В ней один автотест на Python + pytest для СОФР (модуль «Ценные бумаги», БОЦБ) и тест-кейс, по которому он написан.

## Состав

| Файл | Что это |
|---|---|
| `ТК 526914.xlsx` | Тест-кейс: 19 шагов с ожидаемыми результатами |
| `test_526914.py` | Автотест по этому кейсу |
| `test_526914.atm` | Макрос для СОФР, который генерирует автотест |

Такой же файл кейса лежит в папке RTF под именем `ТК 526914 (1).xlsx`, см. [../rtf-autotests/README.md](../rtf-autotests/README.md).

## Тест-кейс 526914 «Еженедельный отчёт по сделкам РЕПО»

Кейс проверяет выпуск регламентированного отчёта для уполномоченных представителей Банка России:

1. Открыть форму отчёта в меню «Ценные бумаги», задать период, выпустить отчёт.
2. Проверить имя файла и папку, куда он сохранён.
3. Проверить запись о выпуске в таблице `DDL_REPORT_REPO_DBT`: идентификатор, период, системная дата и время, операционный день, операционист, признак ошибки.
4. Открыть Excel-файл, проверить заголовок, затем 9 граф по очереди, затем сортировку строк.

**Недочёты в самом кейсе:**

- **Копипаст из других кейсов.** В шаге 2 прогресс-бар назван «Формирование отчета Контроль выплат по % СВОПам» — это другой отчёт. В шаге 18 для графы 9 («на конец периода») ожидаемый результат описывает начало периода.
- **Формат файла не совпадает с тестом.** Кейс ждёт `.xls`, автотест ищет `.xlsx`.
- **Нефункциональное требование без проверки.** «Выпуск за 7 дней не должен превышать 20 минут» записано в ожидаемом результате, отдельного шага для него нет.

## Автотест `test_526914.py`

**Устройство:**

1. **Сборка макроса.** Функция `build_atm` через кодогенератор `ATM` собирает сценарий для клиента СОФР: выбор подсистемы, пункт меню, заполнение полей формы по номерам, ожидание появления и закрытия окон. Результат — макрос `.atm`, как в папке.
2. **Запуск.** `controller` запускает макрос и следит за логом воспроизведения, таймаут — час.
3. **Проверки.** Тест находит файл отчёта, сверяет запись в БД СОФР и проверяет Excel через `openpyxl`.

Отчёт в Allure и Test IT идёт через `reporting`, тест помечен `AT_RT`.

**Что сделано хорошо:**

- сценарий в клиенте генерируется из кода, а не записывается вручную;
- каждая графа отчёта проверяется отдельным шагом с названием из кейса;
- у проверок записи в БД есть сообщения;
- файл отчёта прикладывается к Allure.

**Замечания:**

- **Тест подогнан под реализацию.** По кейсу заголовок — «за период с <Д1>г. по <Д2>г.», даты в формате DD.MM.YYYY. Тест убирает ведущий ноль у дат и ждёт двойные пробелы: `'за период с  1.06.2026 по  6.06.2026'`. То есть отклонение от требования закреплено в тесте как норма.
- **Запись в БД не привязана к запуску.** Тест берёт последнюю запись за период (`ORDER BY t_ID DESC`) и не проверяет, что она появилась после старта. Период зашит, поэтому если в этот раз запись не создалась, тест проверит запись от прошлого прогона и пройдёт.
- **Период зашит:** 01.06.2026–06.06.2026. Результат зависит от того, какие сделки есть на стенде за эти даты.
- **Графы проверяются только на заполненность.**
  - Контрагент и эмитент — `is not None`, суммы — «число ли это». Сверки с карточкой сделки, остатками и курсом ЦБ, которых требует кейс, нет.
  - Валюта — только `RUB`. Сделка в другой валюте уронит тест, хотя отчёт будет верным.
- **Строки 6–16 зашиты.** Если сделок меньше 11 (`sheet[6:16]` в openpyxl включает обе границы), в пустых ячейках `None`: `x.isdigit()` упадёт с `AttributeError`, а `float(None)` в `try_parse_money` — с `TypeError`, который функция не ловит. Строки после 16-й не проверяются вовсе.
- **Сортировка проверяется по строкам.** Номер сделки сравнивается как текст, поэтому «10» окажется раньше «9».
- **Файл берётся первым из списка** (`report_files_list[0]`). Проверки, что список не пуст и что файл один, нет. Формат имени файла из шага 3 кейса не проверяется.
- **Требование «не дольше 20 минут» не проверяется.** Таймаут ожидания — 3600 секунд.
- **Подстановка в SQL.** Период подставляется в запрос через `{period}`, а `;` в конце текста запроса может не пройти через драйвер.
- **Макрос в папке не совпадает с кодом.** В `.atm` есть `PanelOff("Копирование на терминал")`, а в `build_atm` эта строка закомментирована и заменена на `subscribe_panel`. Видимо, макрос сгенерирован из более старой версии теста.

## Что полезно для конкурса

- **Пара «кейс + автотест».** По ней удобно делать задание на пункт 1 чек-листа автотестов: покрывает ли автотест кейс. Здесь расхождений много:
  - тест подогнан под формат заголовка;
  - не проверяются имя файла и время выпуска;
  - графы проверяются только на заполненность.
- **Образец стиля Python для 1д.** pytest-фикстуры (`controller`, `sofr_db`, `excel_handler`), шаги через `reporting.step`, проверки на `assert` с сообщениями. Это другой стиль, чем у СИ (PyHamcrest), — его стоит учесть при выборе образца.
- **Готовые дефекты для SQL-части 1д:**
  - «последняя запись» без привязки к запуску теста;
  - подстановка параметра в текст запроса;
  - зашитый период.
- **Специфика БОЦБ.** Тест работает с толстым клиентом через макросы. Ревью такого кода требует знания внутреннего инструмента, поэтому в задание его стоит брать только в части проверок.
