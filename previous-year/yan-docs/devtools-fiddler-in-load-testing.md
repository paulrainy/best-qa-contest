# Анализ и отладка: DevTools и Fiddler в НТ: выжимка

Выжимка из документа «Анализ и отладка DevTools и Fiddler в НТ_KEA». Учебный модуль для инженеров НТ: как записывать и анализировать HTTP-трафик, искать запросы для корреляции и смотреть трафик JMeter через Fiddler. В оригинале 36 скриншотов; пример строится на Grafana.

## Запись и просмотр трафика

| Действие | DevTools (браузер, F12) | Fiddler |
|---|---|---|
| Запись | Вкладка Network, запись идёт при красном индикаторе. Обновить страницу | Пишет сразу после запуска. Кнопка «Capturing» включает и выключает запись |
| Детали запроса | Вкладки Headers, Payload, Preview, Response, Initiator, Timing, Cookies. Заголовки и куки показаны отдельно для запроса и ответа | Двойной клик по запросу |
| Сохранение | Кнопка «Скачать» → HAR | File → Export Sessions → All (или Selected) → HTTPArchive v1.1 |
| Поиск | Значок поиска по всем запросам. Двойной клик по результату ведёт к запросу | «Find»: найденные запросы подсвечиваются выбранным цветом |

HAR из DevTools можно открыть в Fiddler и любом другом инструменте, который понимает HAR.

## Поиск запроса для корреляции

**Сценарий.** После авторизации сервер выдаёт признак сессии (куку, заголовок или поле тела), и клиент передаёт его во всех следующих запросах. Для корреляции в скрипте НТ нужно:

1. найти первый ответ, в котором клиент получил признак;
2. вытащить значение экстрактором;
3. подставить в следующие запросы.

Модуль разбирает шаг 1 на примере куки `grafana_session`.

- **DevTools:**
  - включить «Preserve log» и залогиниться;
  - фильтр «Fetch/XHR»;
  - в последнем запросе найти куку;
  - поиск `cookie-name:grafana_session`, сортировка по Waterfall (хронология);
  - первый запрос — `login`; на вкладке Cookies кука есть в Response Cookies.
- **Fiddler:**
  - скопировать значение куки → «Find Sessions»;
  - отсортировать по номеру сессии;
  - первый подсвеченный запрос — `login`; проверить куки в ответе.

## JMeter + Fiddler

**Зачем.** Если тела запросов очень большие, GUI JMeter не может их показать и зависает.

1. Добавить в тест-план HTTP Request Defaults. На вкладке Advanced в блоке Proxy Server указать `localhost`, порт `8888`.
2. В Fiddler выключить «Capturing», чтобы он не перехватывал системный трафик и писал только запросы, пришедшие на прокси от JMeter.
3. Запустить скрипт и смотреть трафик в Fiddler.

## Замечание

Модуль не говорит про HTTPS. Чтобы Fiddler видел содержимое HTTPS-запросов JMeter, нужно включить расшифровку HTTPS в Fiddler и сделать так, чтобы JMeter доверял его корневому сертификату (или отключить проверку сертификатов). Иначе будет виден только CONNECT-туннель.

## Что полезно для конкурса

- Корреляция — ключевой навык скриптописателя НТ. Возможное задание: дать HAR-файл и попросить найти, откуда берётся динамический параметр и каким экстрактором его достать.
- Вопрос с подвохом: почему при поиске признака сессии нужна хронологическая сортировка и «Preserve log».
